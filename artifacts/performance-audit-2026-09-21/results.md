# Результаты оптимизации

Ветка: `codex/frontend-performance`. Приложение не опубликовано; production-метрики пока не изменились. Новая production-сборка успешно собрана из текущих исходников 63.8.0.

## Выполненные изменения

1. **Ранний клик:** лёгкий inline-обработчик сохраняет одно действие Create room, показывает aria-busy и выполняет его после гидратации. Проверены первый клик, закрытие и повторное открытие формы. Изменение маршрута/удаление кнопки отменяет отложенный клик.
2. **Иконки-картинки:** существующий генератор Sharp создаёт 128px миниатюры для маленьких ролей, дополнений и команд. Большие портреты, карточки и варианты оформления сохранены. 64 миниатюры суммарно занимают 181 036 байт вместо 4 951 340 байт оригиналов (−96,3%).
3. **Premium:** текст остаётся в prerendered HTML, но изображения не получают src до первого раскрытия раздела. После закрытия изображения не размонтируются. Поддерживается раскрытие до гидратации и native keyboard interaction.
4. **Material Icons:** вместо полной библиотеки используется проверенное подмножество: 125 116 → 13 128 байт (−89,5%). Сохранены динамические имена, псевдоэлементы и алиасы Vuetify, зарезервированы размеры иконок. Python нужен только для редкой регенерации; обычная сборка использует готовые файлы.
5. **JS/CSS:** Lobby, формы входа/изменения данных и содержимое achievement popup отделены от стартового пути. Обработчики событий остаются в лёгкой оболочке, поэтому события открытия не теряются. Preload включает зависимости конкретного маршрута, но исключает серверный рендерер сборки. Ожидание полных стилей перед активацией сохранено.
6. **Аналитика:** очереди создаются сразу; SDK загружаются после готовности приложения, отложенной задачи и idle callback. Ранний уход обрабатывается best-effort по visibilitychange. Дедупликация, исключение prerender и password-recovery сохранены. Доставка аналитики при немедленном закрытии страницы, как и прежде, не гарантируется.

## Сравнение локальных сборок

У сохранённого исходного dist версия **63.6.0**, у новой сборки **63.8.0**. Пользователь подтвердил, что промежуточные версии содержали визуальные изменения, и попросил не пересобирать отдельную базовую версию. Поэтому таблица описывает сравнение этих двух артефактов, а не изолированный эксперимент над одним и тем же коммитом.

Одинаковые условия: Chrome, 390×844, DPR 1, CPU ×4, 200 000 байт/с download, задержка 150 мс, отключённый HTTP-кэш, локальная раздача gzip. Картинки из cloud URL направлялись на локальные файлы соответствующей сборки. Внешняя аналитика и backend-соединения заблокированы в обоих вариантах. Сервер/DNS/TLS production здесь не измеряются. На главной три последовательных прогона; на rules и support по одному. Для локальной гидратации фиксировалось появление Vue app на корневом DOM-элементе с интервалом наблюдения 20 мс.

| Показатель                                                  |         До |     После | Изменение |
| ----------------------------------------------------------- | ---------: | --------: | --------: |
| Гидратация главной, медиана                                 |     3,23 с |    2,48 с |    −23,1% |
| Ресурсы главной до load + 0,5 с, медиана\*                  |  488,9 КиБ | 345,5 КиБ |    −29,3% |
| Изображения rules в этом окне                               | 1106,2 КиБ |  41,2 КиБ |    −96,3% |
| Внешние CSS главной, gzip                                   |   65,8 КиБ |  45,8 КиБ |    −30,4% |
| Полный стартовый JS главной со словарём и route chunk, gzip |  300,7 КиБ | 286,6 КиБ |     −4,7% |
| WOFF2 иконок                                                |  122,2 КиБ |  12,8 КиБ |    −89,5% |

\* Сумма encodedBodySize ресурсов, без основного HTML. Нельзя сравнивать её с полным HAR transfer size или трафиком production с аналитикой и живыми игровыми данными.

LCP главной практически не изменился: медиана 0,301 → 0,305 с. Это ожидаемо: prerender и раньше быстро показывал текст. Основной выигрыш — готовность интерфейса и расход трафика. В единичных тестах rules гидратация составила 8,10 → 2,95 с, support 5,16 → 2,55 с; эти значения не следует трактовать как устойчивый p75 или обещание production-эффекта.

На новой support до раскрытия premium-блока не запрашиваются его анимации и стикеры. Проверка гарантирует отсутствие самих запросов; это надёжнее, чем полагаться только на браузерный loading=lazy.

## Проверки

`npm run build:ui` завершился с кодом 0:

- 64 модульных теста;
- prerender 192 страниц, максимальный критический CSS 6,9 КиБ gzip;
- 4 проверки structured data;
- гидратация и сохранность LCP-узлов на шести языках, SPA-навигация, язык/тема возвращающегося пользователя;
- проверки восстановления пароля и страницы поддержки;
- отдельный browser regression раннего клика, повторного открытия входа, отсутствия чанков Lobby/диалогов на статье и раскрытия premium до гидратации;
- контроль всех 227 файлов изображений и 607 CSS/SEO-ссылок;
- бюджет JS/CSS полного входа каждого маршрута, запрет preload build-only renderer, бюджет шрифта 25 КиБ;
- независимый code review; замечания об импорте уведомлений и preload рендерера исправлены.

Бюджет обычных страниц: JS ≤365 КиБ gzip, CSS ≤50 КиБ gzip. Для страниц графиков — ≤480 и ≤55 КиБ соответственно. Стартовая оболочка без словаря/route chunk: 244,6 КиБ gzip. Счётчики аналитики не входят в бюджеты собственных ресурсов.

Мобильные снимки главной, правил и раскрытой галереи проверены визуально. На снимке поддержки backend заблокирован намеренно: сообщение о недоступности API не является ошибкой production.

Приватные игровые действия и реальные изменения учётных данных не выполнялись. Полевые INP/LCP/CLS можно оценить только после публикации и сбора пользовательских данных. Рекомендуется использовать существующий процесс выпуска, включая загрузку новых хэшированных изображений; одной замены HTML недостаточно.
