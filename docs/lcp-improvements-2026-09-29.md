## Выполненные изменения

### 1. Наблюдение за реальными посетителями

Официальная библиотека Google `web-vitals@6.2.2` отправляет событие `web_vital` через уже существующую очередь Google Analytics. Она загружается отдельным чанком, не блокирует запуск приложения и не загружается при сборочном пререндере, в DEV или при прямом открытии приватной страницы. Ошибка её загрузки не мешает приложению. Стоимость диагностического чанка проверяется отдельно; существующие бюджеты стартового JS не повышались.

Измеряются LCP, INP, CLS, FCP, TTFB. LCP включает TTFB, задержку обнаружения ресурса, его загрузку и задержку отрисовки. TTFB разделён на ожидание, кеш, DNS, соединение и запрос. INP разделён на задержку ввода, обработку и представление кадра.

Контекст: версия сборки, известный публичный шаблон/локаль, диапазон ширины экрана, тип навигации и ограниченная категория элемента. Полные селекторы, DOM-текст, URL ресурсов, адреса комнат, ID пользователей, query и hash в payload не включаются. Автоматические поля GA `page_location`, `page_referrer`, `page_title` переопределены безопасными значениями для этих событий. Это не меняет настройки других уже существующих событий аналитики.

LCP/FCP/TTFB первоначальной публичной страницы сохраняются, даже если callback сработал после входа в комнату. INP/CLS не отправляются, когда текущий путь приватный. После BFCache-восстановления контекст фиксируется заново в capture-обработчике `pageshow`, раньше обработчиков библиотеки.

### 2. Декоративные изображения главной

Две карточки 104×150 CSS px используют существующие 512px avatar-версии вместо полноразмерных картинок. Сумма файлов: **100 560 → 33 778 байт (−66,4%, экономия 66 782 байта)**. Большие портреты в остальных местах сохраняются. На экранах до 1000 px блок по-прежнему скрыт. Это уменьшение этих двух ресурсов, не обещание такого же процента улучшения LCP. В предыдущем mobile Lighthouse LCP был текстом.

Иконочный subset регенерирован штатным инструментом: консервативный сканер проекта считает слова `attribution` и `forward` потенциальными именами иконок. Шрифт остаётся в прежнем бюджете (14 080 байт; исходно 14 056).

## Как читать новые метрики после публикации

1. В GA4 проверить поступление события `web_vital`. В тестах внешняя доставка заблокирована: проверяется очередь, а не приём сервером GA.
2. Для разрезов зарегистрировать параметры `metric_name`, `app_version`, `page_route`, `page_locale`, `viewport`, `navigation_type`, `metric_target` как event-scoped dimensions. `metric_value` и длительности — custom metrics; CLS без единицы времени, остальные значения в миллисекундах. `viewport` не заменяет штатную категорию устройства GA. Страну брать из существующего географического разреза GA, не определять по языку страницы.
3. `metric_id` — случайный идентификатор экземпляра метрики библиотеки, не пользователя. Не регистрировать его как высококардинальную UI dimension; он нужен для дедупликации в экспорте. Для каждого ID брать запись с максимальным `metric_sequence`, затем считать p75 по метрике/версии/странице/устройству/стране. Нельзя усреднять p75 отдельных стран или брать среднее всех callback-значений. GA4 среднее значение не заменяет p75; для точного анализа использовать экспорт событий, например BigQuery, если он подключён.
4. При сравнении загрузок отделять `back-forward-cache`, reload и обычные navigate. BFCache законно может давать почти нулевой TTFB. Soft navigation отключены; `spa_changed=1` означает, что callback пришёл уже на другом маршруте, а контекст относится к исходной навигации документа/восстановлению.
5. Это RUM доступных аналитике посещений. Блокировщики, отсутствие JS и уход до загрузки диагностического чанка уменьшают выборку. INP/CLS здесь не покрывают всю приватную игровую сессию. Результаты не обязаны совпадать с выборкой Chrome CrUX.

Настройки GA4, BigQuery и production в рамках изменения не переключались. Без публикации новая телеметрия не появится. Перед выпуском пройти обычный процесс выкладки UI и проверки доступности изображений.

## Следующий этап с наибольшим потенциалом: CDN публичных страниц

Региональные результаты делают доставку HTML ближе к посетителю более приоритетной, чем очередное общее сокращение JS. Подключение требует выбора доступного CDN и настройки домена; провайдер, аккаунт и DNS в этом изменении не менялись.

Требования к внедрению:

- Кешировать только явно перечисленные публичные пререндеренные HTML-страницы; стартовый edge TTL 300 с с очисткой при выпуске. Браузер может сохранять нынешнюю обязательную ревалидацию HTML. Текущий `no-cache` сам по себе не даёт CDN права отдавать устаревший ответ без проверки: потребуется явная политика edge-кеша.
- Хэшированные JS/CSS/fonts — долгий immutable-кеш. Сначала публиковать новые ресурсы, затем HTML; старые хэши сохранять на время перехода и отката.
- `/api/`, `/socket.io`, комнаты, профиль, восстановление пароля и пользовательские страницы обходят HTML-кеш. Проверить websocket Upgrade и длительную игровую сессию через выбранный провайдер. Голосовой транспорт и отдельный voice-host не переводить на HTTP CDN автоматически.
- Редиректы, 404, языковые URL, canonical, sitemap и `noindex` сохраняются. Ошибки и приватные ответы не должны становиться публичными кешированными страницами.
- Контроль после включения: подтверждённый HIT для публичного HTML, отсутствие HIT на приватных/API, повторные замеры из TW/DE/US, RUM по версии и стране, проверка релиза/отката. Уменьшение TTFB не гарантирует прохождения LCP без проверки рендера.

## Проверка

Модульные тесты покрывают allowlist путей, фильтрацию payload, дедупликацию, поздний LCP после перехода в комнату и BFCache-контекст. Браузерный `check-web-vitals.cjs` проверяет реальный LCP/TTFB через очередь GA без внешней отправки, исключение приватного старта/восстановления пароля и симулированный persisted `pageshow` для порядка обработчиков TTFB. Последнее — проверка обработки события, не полный тест естественной BFCache-эвакуации браузером.

Полный `npm run build:ui` с установленным Chrome (`PUPPETEER_EXECUTABLE_PATH`) завершился с кодом 0: 197 модульных тестов, 4 structured-data теста, 192 пререндеренные страницы / 186 sitemap URL, сохранение LCP-узлов на шести языках, проверки навигации, восстановления пароля, поддержки, раннего клика и новых метрик. Стартовая оболочка 247,0 КиБ gzip, с английским словарём 285,0 КиБ; независимый диагностический чанк 6,7 КиБ gzip. Бюджеты каждого маршрута и иконочного шрифта соблюдены; проверены 228 исходных изображений и 607 CSS/SEO-ссылок. `git diff --check` проходит. Независимое ревью не нашло оставшихся замечаний.

Сборка выдаёт 18 предупреждений: конфликт определения Vue hydration diagnostics, порядок CSS, рекомендуемые размеры assets/entrypoint и выделение webpack runtime. Предупреждения не подавлялись; чистая сборка без предупреждений не заявляется. Начальные попытки упирались в ограничение среды/отсутствующую Puppeteer-версию Chrome, затем использован уже установленный Chrome. Отдельный полный multiplayer/voice-сеанс не проверялся. Глобальный полевой LCP после этих изменений ещё не измерен.
