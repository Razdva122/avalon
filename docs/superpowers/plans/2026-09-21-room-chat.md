# Room chat implementation plan

Goal: implement the approved adaptive game-chat design while preserving the current sticker controls and 110 px avatar reactions.

Architecture: server-confirmed, idempotent text messages; a room-scoped chat controller handles reading and outgoing state; the chat panel owns scrolling, mobile viewport layout and profile dialogs. Board previews are passive text bubbles; own messages remain visible with the chat open.

- [x] Add message IDs, delivery acknowledgements and retry deduplication. Test validation and duplicate requests.
- [x] Add a tested chat controller for unread messages, room reset and pending/failed sends.
- [x] Replace the compact/full chat modes with closed/open adaptive panel, grouped messages, timestamps, unread boundary, jump button, multiline input and compact profile dialog.
- [x] Add short readable board previews with author attachment; suppress other-player previews while chat is open, preserving own previews. Preserve sticker reactions and game indicators.
- [x] Add translated UI strings and responsive overlay layout without moving the game board and respecting the mobile keyboard.
- [x] Run frontend tests, targeted backend tests, type/build checks and browser checks; review the final diff.

Validation: 58 frontend tests, 4 targeted backend tests, backend TypeScript check, development UI build and formatting passed. Local Chromium harness exercised real Chat/Player components with simulated message delivery: scroll preservation, unread state, retry, profile dialog, board-to-history navigation, both themes, portrait and landscape viewport/keyboard handling. A live multiplayer session and physical mobile keyboards were not tested. Temporary preview entry removed.

Follow-up: removed the read-in-chat action, kept own board previews with the chat open, removed desktop table displacement, and simplified clicked profiles to avatar/name/two statistics.
