# AI room implementation plan

Goal: create a spectator room with seven Qwen bots and bounded English discussion, using the existing Avalon engine.
Spec: ../specs/2026-09-21-ai-avalon-experiment.md. User approved implementation on 2026-09-21.

Architecture: BotRoom extends Room, owns one sequential coordinator; Yandex client gets only player-visible state. Mongo stores a shared atomic budget ledger and AI-only replay documents, separate from ranked rooms. Socket handlers expose allowlisted admin controls and public availability. Existing board/chat display the match.

Constraints: seven fixed seats, Merlin/Percival/two servants/Mordred/Morgana/minion and Lady of Lake. No human seats yet. No automatic rematches. No ratings/achievements. No new dependencies. API secret stays in ignored .env.local. Use confirmed Qwen3.6 endpoint with reasoning_effort=none. Default cap: 500 RUB total, 100 RUB per match, configurable downwards; no automatic budget reset. Grant is not a reason to remove caps.

- [x] Tests first: complete deterministic game through Lady and assassination, no secret-role leakage, cancellation discards in-flight results, malformed decisions have legal fallback.
- [x] Add ai/client.ts: bounded JSON decisions, timeout, no secret logging. Atomic reservation before requests, reconcile usage, preserve timeout reservations.
- [x] Add ai/repository.ts: Mongo budget reservations and isolated replays. Tests using mongodb-memory-server for concurrent reservations and persistence.

- [x] Integrate main/index.ts: admin login allowlist, only one active AI room, public status, profile lookup for synthetic bots, isolated replay save/load, block ordinary game controls.
