# Community player boards

Approved in chat: implement the first version on the existing Community page, above existing server listings. Two boards: solo (looking for company) and group (looking for players). Signed-in users may publish solo; group requires participation in at least one completed non-manual game, checked server-side. One persistent listing per user per board. No free-form descriptions or comments.

Listings contain languages (en,ru,es,pt,cmn,yue), days (1 Monday through 7 Sunday), local start/end hour 0..23, IANA timezone, voice/text/either, beginner/experienced experience, beginnerFriendly boolean, canTeach boolean, groupSize and seeking count for group (total <=10), and one or two contacts: wechat,qq,line,discord,telegram. Contacts use account IDs only for MVP; qqGroup optional contact type for group only. Publicly displayed contacts with copy buttons; no arbitrary URLs or HTML. UI explains contacts are public. Nick/avatar come from current profile.

Publish/reactivate lasts 30 days; bump once per 7 days, with initial publication counting as bump. Edit never extends expiry or changes rank. Hide preserves data and cooldown; reactivation is available only when 7-day ranking cooldown has passed (prevents hide/reactivate bypass). Expired records retained, excluded by expiry in reads (no destructive TTL). Server atomic predicates and unique indexes enforce concurrency. Default newest bump first, language filter, paginated browsing.

Signed-in people can report using spam/abuse/contact reasons, deduplicated per reporter and listing. Admin can inspect reports, hide listings, ban/unban board publishing. Reports never auto-hide. Banned authors excluded from public results. Bans enforced on create/update/reactivate/bump. Owner reads include inactive listings, ban and eligibility state. All write actions authenticated; admin authority read from DB.

REST API under /api/player-boards. Shared DTOs in packages/types/player-board.ts. GET /?kind=solo|group&language=...&page=1 -> { listings: BoardListing[], hasMore:boolean }. GET /me -> { listings: BoardListing[], canRecruit:boolean, banned:boolean, isAdmin:boolean }. PUT /me/:kind body BoardDraft -> {listing:BoardListing}; POST /me/:kind/:action (bump|hide|reactivate) -> {listing:BoardListing}. POST /:id/report {reason} -> {ok:true}. GET /moderation -> {reports: BoardReport[]}; POST /moderation/:id/hide; POST /moderation/users/:userID/ban {banned:boolean}; POST /moderation/:id/dismiss. Errors {error:string}.

BoardListing = BoardDraft plus id,userID,name,avatar,createdAt,bumpedAt,expiresAt (ISO strings), active:boolean,moderated:boolean. BoardDraft = kind,languages:string[],days:number[],startHour:number,endHour:number,timeZone:string,communication:'voice'|'text'|'either',experience:'beginner'|'experienced',beginnerFriendly:boolean,canTeach:boolean,groupSize:number,seeking:number,contacts:{type:BoardContactType,value:string}[]. BoardReport = id,listing:BoardListing, reasons:string[],count:number,banned:boolean. Shared constants BOARD_LANGUAGES [{value,title}], BOARD_CONTACT_TYPES, BOARD_KINDS. All six existing interface locales supported, especially zh-CN and zh-TW. Time shown in author's explicitly named timezone (never falsely claim visitor conversion); local conversion may be added with correct day rollover handling.

Validation tests cover expiry boundaries, cooldown, ownership, eligibility, malicious payloads, reports/admin, pagination, concurrency, and actual HTTP/Mongo integration. UI uses existing Vue/Vuetify/theme patterns, labelled inputs and responsive cards, clear empty/loading/error feedback, and token changes refresh private state. No publishing or deployment.
