# Восстановление пароля и служебная почта

Согласовано: восстановление на текущий сохранённый email, включая старые аккаунты. Подтверждения email и массовых рассылок нет. Смена email по текущему паролю остаётся доступной.

## Поведение

Форма входа ведёт на страницу восстановления. Запрос всегда получает нейтральное подтверждение; отсутствующий аккаунт, подавленный адрес и адресный лимит не раскрываются. При общей недоступности сервиса показывается ошибка, при IP-лимите — предложение попробовать позже. Ссылка действует 30 минут. GET не расходует её. После POST с новым паролем все ссылки и сессии отзываются, вход выполняется вручную. Отправляется уведомление о смене пароля.

## Хранение и безопасность

32 случайных байта в токене, SHA-256 для проверки. Секрет письма в очереди зашифрован AES-256-GCM отдельным ключом. Очередь и хеши ссылок находятся в документе пользователя: создание ссылки с задачей, а также смена пароля с погашением всех ссылок и уведомлением атомарны без требования replica set. Повторный запрос не гасит предыдущие непросроченные ссылки. Смена email/пароля через настройки также гасит ссылки.

JWT содержит версию авторизации. HTTP и WebSocket сверяют её с БД; старые JWT без версии соответствуют версии 0. WebSocket проверяется при подключении и перед каждым событием; после сброса локальные соединения закрываются немедленно, соединения других процессов — при следующем событии или периодической проверке.

Ссылка содержит токен во fragment, который не передаётся в HTTP access log. Страница удаляет fragment из адресной строки и не загружает аналитику при прямом открытии. Referrer-Policy: no-referrer, Cache-Control: no-store. Новые пароли соответствуют существующему минимуму 8 символов; верхний предел bcrypt — 72 байта, пробелы запрещены как в существующем UI.

## Защита отправки

Общие для процессов скользящие ограничения MongoDB: адрес — 1 запрос/2 минуты, 3/час, 5/сутки; IP — 10/15 минут; сброс по токену — 10/15 минут/IP; глобально по умолчанию 1000 отправок/час и 5000/сутки, настраиваемо. Лимиты не блокируют вход. Поле IP берётся из сокета либо из доверенного proxy, который перезаписывает X-Forwarded-For.

Worker забирает задачу атомарно, шлёт только фиксированные шаблоны через Postbox SMTP/TLS. После успешной отправки зашифрованное содержимое удаляется. Повторяет только однозначные временные SMTP 4xx с задержкой, максимум 3 попытки. Неопределённый результат отправки не повторяется автоматически, поскольку SMTP не гарантирует exactly-once. Просроченные и отозванные задачи удаляются. Вне production действует обязательный allowlist получателей.

Подписанный инфраструктурой мост событий Postbox передаёт Bounce/Complaint на endpoint с отдельным секретом. Permanent Bounce и Complaint включают suppression по адресу. Никаких публичных неаутентифицированных callback. Нужны настройка событий в Yandex Cloud, DKIM/SPF/DMARC, мониторинг структурированных событий worker и контроль квот до включения production.

## Включение и проверка

Без MAIL_ENABLED=true и полного набора настроек отправка выключена. Секреты только в окружении/.env.local. Тесты используют отдельную временную MongoDB, фиктивный SMTP transport и локальный HTTP сервер; реальные письма не отправляют. Проверить конкурентные запросы/сбросы, TTL, лимиты, отсутствие раскрытия аккаунтов, отзыв JWT, подавление адресов, повторные попытки и production сборку интерфейса.
