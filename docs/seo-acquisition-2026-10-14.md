# International SEO acquisition — 14 October 2026

## Scope and basis

The owner selected international acquisition and approved starting parallel implementation. The first batch serves players of Secret Hitler and classic Werewolf/Mafia and organizers choosing a game for 5–10 friends. The owner subsequently requested that bot play be explicitly offered too: the articles provide solo/small-group learning and link directly to the existing lobby AI launch control through `/#play-with-ai`. The owner subsequently requested full translations into all supported languages: English, Russian, Spanish, Portuguese, Simplified Chinese and Traditional Chinese. The three articles therefore have 18 public language URLs, with localized text, metadata, links and breadcrumbs. The detailed implementation contract is in [the spec](superpowers/specs/2026-10-14-seo-acquisition-launch.md) and [the implementation plan](superpowers/plans/2026-10-14-seo-acquisition-launch.md).

The owner further asked to remove the temporary one/two-friend cap from public copy. The guides therefore describe solo play or inviting friends with bots filling empty seats, while setup exposes the currently available table sizes and Premium requirements. The current backend limits remain in force; this copy update does not claim that unlimited seats already work or implement that future behavior.

Public production HTTP checks on 14 October confirmed working indexable home/rules/community pages, canonical and language alternates, and a sitemap with 198 URLs, with no comparison/alternative guide URLs. These observations describe production before the new release.

The repository's [historical Search Console snapshot](seo-baseline-2026-09-25.json) covers 28 August–25 September 2026: traditional Chinese home 932 clicks, English home 619, English rules 561. Those figures are site clicks in an older period, not worldwide query volumes, country distribution, current results or acquisition conversion. They do not establish demand for the new comparison queries in any language. The full six-language release follows the owner’s request; query demand and conversion still require measurement separately per locale.

### Event contracts

All new events use the existing `window.gtag` bootstrap. Optional `guide_slug` always describes the first allowlisted guide encountered in this browser tab; `page_location` is fixed to an allowlisted public guide URL with the current supported locale prefix for guide events and the site root for signup/room events. `page_referrer` is explicitly empty. The events never include account identity, email, room/game identifiers, arbitrary URL/query parameters or raw referrers.

| Event                 | Trigger and scope                                                                                                                                           | Additional field                                                  |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `guide_visit`         | A guide actually mounts, or the shared guide component changes to another article; never prerender.                                                         | None; fixed page location identifies the currently visited guide. |
| `guide_cta`           | Ordinary unmodified primary click on a guide's friends, bots or community action.                                                                           | `destination`: `lobby`, `ai` or `community`.                      |
| `sign_up`             | A registration dispatch returns success; never a login or rejected attempt.                                                                                 | None.                                                             |
| `room_participation`  | An authenticated user is present in a non-archived human room/game roster, before a game or during an unfinished game; once per room in this page lifetime. | None.                                                             |
| `human_game_complete` | The same observed participant's unfinished human game receives a live backend end update with a winner; once per game in this page lifetime.                | None.                                                             |

Spectators, AI rooms, archived games, already-finished snapshots and manually cancelled games do not produce completion events. The tracker observes server state before replay/history rendering, so moving the history pointer does not create or suppress live completion. Supported rematches receive a new room/game UUID, kept only inside the tracker for deduplication.

The initial guide slug is stored in guarded sessionStorage, with a memory fallback if storage is blocked. The separate one-shot friends/bots/community play intent exists only in memory and is consumed after successful auth, including when the current destination no longer matches. Friends and bot actions both retain the lobby context, including an opened AI setup; community actions retain the matching community context. A guide visit alone does not change normal profile/welcome registration. Room-link registration always remains in its room; ordinary registration retains profile and welcome behavior.

Bot CTA clicks are reported separately as `destination: ai`. The participation/completion events above deliberately continue to measure ordinary human games. Bot-game completion is not added to that funnel or represented as a human game. The site's existing AI results/statistics remain separate.

Play intent and event deduplication do not survive a full page reload. No offline completion backfill, cross-session attribution, first-ever-player marker or retention dashboard is included. Missing or throwing analytics does not interrupt navigation/auth/gameplay; successful provider delivery remains a post-release check. Register `guide_slug` and `destination` as event-scoped dimensions in the analytics account and configure relevant funnel/key-event reports after publication. These client changes do not alter existing analytics bootstrap page-view behavior.

After publication, record the actual deployment date and verify all 18 live language URLs, sitemap and metadata. Fresh Search Console inspection/submission should use the published canonical URLs. Compare equal completed 28-day periods, separating guide pages, language, country and device; monitor queries alongside new human players and game participation. Search Console's aggregate queries cannot be connected to an individual player's game record.

The primary product outcome is a new visitor who completes a first **human** game. Guide visits/CTAs, signup, seated-room participation and live human completion expose the short funnel. Return-within-a-week and first-ever-game reporting need explicitly configured analytics cohorts and a meaningful definition of new versus existing players; client events alone do not establish those measures. Keep AI experiments and human games separate.

If impressions grow but clicks do not, inspect actual query/title/description fit. If clicks grow but human games do not, inspect registration continuity, group availability and setup expectations before commissioning more articles. At low sample sizes, do not infer that an audience or language cannot work.
