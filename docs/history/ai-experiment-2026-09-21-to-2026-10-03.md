# AI-комната Avalon

> Historical record: findings, measurements and plans describe their recorded date. For current setup and operations, use the [documentation index](../README.md).

Первый эксперимент: семь ботов Alice, Ben, Clara, Daniel, Emma, Felix и Grace
обсуждают игру на выбранном языке (английский, русский или традиционный китайский Тайваня), обращаясь друг к другу по номерам 1–7. Номера совпадают с индексами на доске (порядок мест может меняться). Роли: Мерлин, Персиваль, два слуги, Мордред,
Моргана и приспешник; включена Леди Озера. Имена не связаны с ролями.
Зрители видят обычную доску и чат. Сообщения зрителей пока не передаются ботам.
Человеческие места — следующий этап. AI-партии не начисляют рейтинг и достижения.

## Размер стола

Перед созданием AI-комнаты можно выбрать 5, 6, 7 или 8 ботов рядом с моделью
и языком обсуждения. По умолчанию выбираются семь. Новые размеры используют
[рекомендуемые роли из вики](https://avalon-game.com/ru/wiki/rules/#roles-setup):

| Боты | Добро                           | Зло                      | Леди озера |
| ---- | ------------------------------- | ------------------------ | ---------- |
| 5    | Мерлин, Персиваль, Сервант      | Мордред, Моргана         | Нет        |
| 6    | Мерлин, Персиваль, два Серванта | Мордред, Моргана         | Нет        |
| 7    | Мерлин, Персиваль, два Серванта | Мордред, Моргана, Оберон | Да         |
| 8    | Мерлин, Персиваль, три Серванта | Мордред, Моргана, Миньон | Да         |

Состав на семь ботов сохраняет настройку существующего AI-режима. Размер
фиксируется при создании, сохраняется в `ai.playerCount` и отображается
в карточке лобби и панели комнаты. Старые архивы берут размер из списка игроков.
Старые вызовы `createAiRoom(model, callback)` и объекты без `playerCount`
по-прежнему создают семь мест. Новые передают
`createAiRoom({ model, language, playerCount }, callback)`; сервер принимает
только числовые 5, 6, 7 и 8 до резервирования комнаты.

Движок задаёт размеры миссий: 5 игроков — 2/3/2/3/3, 6 — 2/3/4/3/4;
на каждой такой миссии достаточно одной карты провала. Для принятия команды
нужно три голоса из пяти или четыре из шести; ничья отклоняет предложение.
На восемь игроков миссии имеют размер 3/4/4/5/5, четвёртая требует две карты
провала, остальные — одну. Команда принимается пятью голосами из восьми.
Контекст модели содержит действительное число игроков, необходимое большинство,
общее число игроков каждой стороны и публичный состав ролей без привязки к местам.
Мерлин на пяти и шести местах видит Моргану, на восьми — Моргану и Миньона;
Мордред скрыт, отсутствующий Оберон не учитывается как дополнительный злой игрок.

## Настройка

В `packages/backend/.env.local` (не коммитить, права 600) или окружении сервера:

```dotenv
AI_ROOMS_ENABLED=true
YANDEX_API_KEY=<секретный ключ>
YANDEX_FOLDER_ID=<каталог>
YANDEX_MODEL=qwen3.6-35b-a3b
AI_TOTAL_BUDGET_RUB=700
AI_MATCH_BUDGET_RUB=100
```

Модель по умолчанию: `qwen3.6-35b-a3b` через Yandex Chat Completions.
Приватные решения используют reasoning, публичная речь — без reasoning.
Модель фиксируется при создании комнаты, сохраняется в `ai.model` и отображается
в карточке и комнате. Для другой модели необходим настроенный тариф в backend.
Ключ используется только backend. Новых зависимостей нет.

Запуск для разработки при доступной MongoDB:

```sh
NODE_ENV=development npm run start --workspace=packages/backend
NODE_ENV=development npm run serve --workspace=packages/ui -- --host 127.0.0.1 --port 8080
```

Открыть http://localhost:8080, войти под `razdva`, нажать AI Avalon в лобби,
затем Start в комнате. Другие пользователи могут смотреть. Запуск и остановка
проверяются сервером по `UserProfile.isAdmin === true` из базы на каждом запросе.
Список `AI_ROOM_ADMIN_LOGINS` больше не используется. Локальному `razdva` установлен
этот флаг; регистрация и редактирование профиля не позволяют назначить его клиентом.
Одновременно разрешена одна активная AI-комната; автоматического перезапуска нет.

## Ограничения и хранение

700 рублей — общий накопительный потолок, 100 рублей — потолок партии.
Настройки допускают только уменьшение этих значений. Перед каждым запросом
MongoDB атомарно резервирует консервативную оценку стоимости. После ответа
резерв сверяется с usage; при неоднозначном сетевом сбое остаётся зарезервированным.
Стоимость в панели включает такие резервы и не является выпиской провайдера.
Тариф в коде: 0,20 руб./1000 входных и 0,30 руб./1000 выходных токенов с НДС;
перед сменой модели или тарифа нужно обновить расчёт и проверить его.

Регистр расходов `ai_experiment_budget` переживает перезапуск и не обнуляется
автоматически. Это лимит приложения, он не ограничивает прочие расходы Yandex.
Публичные снимки партий лежат отдельно в `ai_room_replays`, доступны по URL комнаты.
После перезапуска незаконченная партия становится остановленной; возобновления нет.
При трёх последовательных ошибках, 400 запросах (450 на восемь ботов)
или превышении денежного лимита — пауза.
Для новой попытки остановить текущую комнату и создать новую. Stop отменяет
текущий запрос и запрещает последующие; провайдер может успеть учесть отменённый запрос.

Каждый бот получает только своё видимое состояние, последние семь реплик ботов
и допустимые действия. Сервер проверяет выбор и применяет его обычным движком.
Корректный формат не гарантирует разумной стратегии: качество обсуждения экспериментальное.

## Обновление обсуждения

В новых комнатах включён `displayIndex`. В запросах вместо имён используются
номера мест, текущий состав команды, номер и размер миссии, порог провала,
свой игрок и результат. Модель получает краткую памятку правил и стратегии:
отличие голосования от миссии, риск злого участника, пятое предложение,
видимость ролей, скрытые карты и правила Леди Озера.

Объявление проверки теперь формируется сервером из того же выбора Good/Evil,
который записывается в историю. Модель может соврать о фактической проверке,
но текст объявления и поле announced больше не выбираются независимо.
После конца игры каждый бот получает раскрытые роли и историю и пишет один
`Post-game:` вывод о результате своей стороны, решающем событии и уроке.
Эти семь дополнительных запросов входят в общие лимиты; остановка, ошибки API
или исчерпание бюджета могут прервать итоговый круг. Старые записи не переписываются.
Наличие правил в запросе не гарантирует понимания: модель может ошибаться,
и качество стратегии следует оценивать по реальным партиям.

## Экономный режим

Сервер ограничивает новые партии 100 рублями, даже если в окружении осталось
старое значение 100. Общий накопительный регистр не сбрасывается.
В модель передаётся компактная проекция: номера и видимые роли, текущая команда,
итоги завершённых миссий и собственные карты, до 25 голосований,
объявления проверок с доступной игроку истиной и 14 реплик до 240 символов.
Полное состояние и внутренние ID не передаются. Это уменьшает расходы и путаницу
между номером места и ID. Старые обсуждения и более ранние голосования модель
может забывать; полный чат и история по-прежнему сохраняются для зрителей.

Перед каждым предложением проходит один публичный круг всех игроков,
по местам начиная с лидера. Боты рекомендуют составы и обсуждают доверие;
это предпочтения, а не голоса или уже выбранная команда. Затем лидер выбирает
окончательный состав с необязательным объявлением. Отдельные решения
approve/reject собираются без реплик и применяются только после выбора всех
ботов. Следующий круг может разбирать реальные прошлые голоса и результаты
миссий. Пятое предложение тоже получает полный круг, после выбора лидера
оно принимается автоматически без голосования. Действие без выбора (например,
карта Success у доброго игрока) выполняется без API. Обычная реплика ограничена
240 символами, итог — 800. Обращения — обычные числа, например “I think 1 and 3 are good”.

Пользователь подтвердил приемлемый предел 20 рублей за полную партию,
включая семь итоговых сообщений. Промежуточная проверка с пределом 10 рублей
и ещё раздельными голосованиями приостановилась после 8,4969 рубля (остатка
не хватило на консервативный резерв); это не цена завершённой партии.

Последнее решение пользователя: оставить Qwen3.6-35b-a3b и поднять предел
до 50 рублей за партию, включая итоги. Alice Flash не использовалась.
Кешированные входные токены учитываются по 0,05 руб./1000 только если API
явно вернул корректный cached_tokens; без этих данных вход учитывается
полностью по 0,20 руб./1000. Резерв по-прежнему считается без скидки кеша.
Для одной и той же завершённой партии компактный контекст сократился с
11 260 до 2 879 байт (на 74%, без системной инструкции).

После каждой публичной реплики бота — пауза 2 секунды при `NODE_ENV=development`,
10 секунд в production и остальных режимах. Это пауза, а не таймаут API. Она применяется также
к объявлению Леди и каждому итоговому выводу, не расходует токены и немедленно
прерывается кнопкой Stop. Генерация следующего ответа может увеличить интервал.
Скрытые игровые действия без сообщений не получают дополнительной задержки.

Список лобби при запуске восстанавливается из обычных игр и `ai_room_replays`.
Записи объединяются по ID, сортируются по времени создания и сохраняют отметку AI;
подключённым зрителям отправляется обновлённый список после загрузки архива.

## AI Arena и согласованность действий

AI-партии в лобби имеют отдельное оформление, статус, время, результат и расход.
Архивные остановленные партии не попадают в фильтр идущих игр.
Модель возвращает точную строку допустимого действия вместо числового индекса.
Голосование не создаёт публичных реплик. Предпочтения в предварительном круге
не связывают последующий голос: бот оценивает окончательный состав после
всех выступлений. Реальные голоса сохраняются в игровой истории.
Применяются короткие персональные инструкции по стороне и роли. В итоговом
контексте есть реальные карты всех игроков и собственные голоса, причём
автоматический пятый состав помечен отдельно от настоящего голосования.
Это улучшает опору на факты, но не гарантирует безошибочной стратегии модели.

Дополнительная стратегия: добро предпочитает безопасные составы со своим участием
и по возможности избегает объединения игроков, активно играющих друг против друга.
Собственное участие не компенсирует злого участника, а конфликт не доказывает роль.
В контекст добавлены номер предложения, будущий лидер пятого предложения и число
отклонений до принудительного похода. Если этот лидер подозрителен, добро должно
искать приемлемый состав раньше, сравнивая риски, а не бесконечно отклонять команды.
Зло получает инструкцию сопоставлять признаки знания Мерлина, отличать их от
блефа и поведения Персиваля и не выдавать свои подозрения добру. Убийство Мерлина
приносит победу только в предусмотренной правилами финальной стадии.

Включение себя в предложенную команду усилено до стандартной стратегии для
обеих сторон: добро заменяет неизвестного участника на заведомо доброго себя,
зло получает возможность сыграть Success ради доверия либо Fail ради победы.
Исключение себя требует конкретной тактической причины. Это предпочтение,
а не запрет допустимых команд; наличие себя не оправдывает опасных спутников.

Перед убийством все три злых бота по очереди предлагают цель и аргументы в закрытом
совете. Каждому передаются накопленные публичные реплики ботов (без голосов,
состоящих только из approve/reject) и предыдущие предложения совета. Назначенный
движком убийца затем выбирает цель с учётом всех трёх предложений. Совет добавляет
три запроса в рамках существующего бюджета; после завершения игры его реплики
публикуются перед итогами. До завершения они не попадают в общий чат или запросы
добрых. Длинный контекст по-прежнему ограничен существующим лимитом API-запроса.
Добрым задано объявлять реальный результат Lady по умолчанию: сама проверка
объясняет источник знания и не требует раскрывать Мерлина. Стратегическая ложь
остаётся разрешена правилами; инструкция не гарантирует послушание модели.

Контекст Qwen разделён по этапам. Выбранный игрок Lady больше не называется
командой: используются proposedTeam, missionTeam и inspectionTarget. Итоги
содержат отдельные assassinations, открытые роли, последнее доступное боту
представление ролей до раскрытия и собственные публичные реплики за всю игру.
Чужие итоговые рассуждения не передаются. История голосов содержит номер миссии,
попытки, лидера и собственный голос; автоматические попытки помечены отдельно.
Для миссий сервер считает счёт, участие бота и допустимое число Fail.
Приватные результаты проверок отделены от публичных заявлений. Системные
инструкции выбираются по этапу, а на итогах отсутствуют указания продолжать блеф.

Эксперимент с отдельными диалогами: в development новые комнаты по умолчанию
используют Responses API и отдельную цепочку previous_response_id для каждого
бота. AI_CONTEXT_MODE=snapshot возвращает прежний режим; AI_CONTEXT_MODE=sessions
явно включает новый в любом окружении. Production без этой настройки остаётся
на прежнем режиме. Сервер передаёт новые публичные сообщения, события миссий,
голосов, проверок и закрытого совета плюс актуальную карточку решения. Приватная
информация берётся только из состояния, доступного этому игроку.
История на стороне провайдера оплачивается; резерв учитывает накопленный контекст
и ответы. При неоднозначной ошибке запросов сессии партия приостанавливается,
чтобы случайный запасной ход не разошёлся с историей модели. Лимиты 50 ₽/партия
и 500 ₽ на эксперимент сохранены. Цепочки живут в процессе комнаты; после
перезапуска незавершённая игра остаётся архивом, продолжение не поддерживается.

Диалоги теперь ограничены: после четырёх ответов одного бота либо при накоплении
12 КБ учтённого контекста следующий запрос начинает новую цепочку. Qwen обновляет
личную заметку memory (до 600 символов) в обычном ответе, без отдельного запроса.
Заметка хранится отдельно для каждого бота и не публикуется. Новая цепочка
получает заметку, факты миссий, голоса, проверки, последние реплики и доступный
совет злых. Факты имеют приоритет над предположениями в памяти. Для заметки
лимит ответа sessions увеличен до 384 токенов (256 для скрытого действия).

Коллекция ai_request_costs хранит одну запись на запрос: комнату, номер игрока,
этап, время, объём контекста, факт сокращения, резерв, input/cached/output tokens,
подтверждённую сумму в единицах 1/10000 ₽ и статус. Prompt, ключи и приватные
заметки в журнал расходов не записываются. reservation-rejected означает, что
запрос не был отправлен; unconfirmed-charge — что сумма API неизвестна и резерв
сохранён. Запись reserved/sent без finishedAt помогает заметить прерванный процесс.
Записи появляются только для новых запросов, старые партии задним числом не детализируются.

В промпт выбора команды и голосования добавлены примеры выводов из собственной
карты и числа Fail, включая неоднозначный случай одного Fail среди двух других
участников. Примеры явно помечены как иллюстрации, а не события партии. Личная
память разделяет Facts, Suspicions и Decision в прежнем лимите 600 символов.
Сервер не вычисляет подозреваемых и не подменяет стратегические решения Qwen.

Для анализа решений новые запросы сохраняются отдельно в ai_decision_traces:
точный payload без HTTP-заголовков/ключей, номер игрока и этап, предыдущая заметка,
ответ модели, выбранное действие и новая заметка. \_id совпадает с записью
ai_request_costs; previous_response_id и responseID позволяют связать историю
цепочки. Выбор модели не гарантирует применение хода (например, Stop может его
отменить): фактически выполненное действие нужно сверять с историей игры.
Это серверная диагностическая коллекция, не часть публичного replay или socket
состояния. memory — краткое объяснение/память, а не внутренние рассуждения модели.
Запись не добавляет API-запросов или токенов. Прошлые несохранённые заметки восстановить нельзя.

Инструкция Lady: добрый бот стремится включать лично проверенного Good во все
составы вместе с собой и предпочитает этот костяк при голосовании. Если проверенный
затем объявляет другого Good, доверие продолжается по направленной цепочке;
источники цепочки сохраняются в личной памяти. Прямой результат — доказательство,
следующее звено зависит от правдивости проверенного. Собственная ложь и объявления
непроверенных игроков доказательством не считаются. Размер команды и риск остальных
участников сохраняют значение. Выводы делает Qwen, не серверный алгоритм.

После разбора партии 6d9bc4ca уточнены инструкции: Reject отклоняет только состав
и не меняет счёт; приватные роли и текущий счёт важнее старой заметки; Lady Good
не исключает Мерлина. На совете нужно сравнить основного кандидата с альтернативой,
а при выборе карты — учитывать близость трёх успехов добра и число нужных Fail.
Память запрашивается как три короткие законченные строки Facts/Suspicions/Decision
(предпочтительно 200–400 символов, предел 600) вместо длинного самообсуждения.
С 3 октября голосование отделено от обсуждения и проходит без реплик;
объяснять прошлые approve/reject боты могут на следующем публичном круге.

## Раздельное решение и публичная речь (22 сентября)

Новые комнаты используют `pipeline.ts`: отдельное приватное решение с коротким
обоснованием, затем независимый запрос публичной речи с зафиксированным действием.
Речь получает только открытые факты: без роли, личных проверок, собственных карт,
совета зла и приватных заметок. Секретная карта, совет зла и итоговый разбор требуют
одного запроса. Ошибка любого этапа ставит игру на паузу без запасного действия.

Переписываемой моделью памяти и цепочки `previous_response_id` в этом режиме нет.
Каждый игрок получает последние четыре собственных решения как ненадёжные заметки,
а факты игры поступают из актуального состояния. Стратегию по-прежнему выбирает Qwen.
Старое описание sessions выше относится к предыдущему режиму транспорта.

Лимит новых партий — 100 ₽, общий накопительный лимит — 500 ₽, журнал не сбрасывается.
`AI_REASONING=default` включает reasoning модели (без указания глубины), `none`
отключает. Публичная речь всегда без reasoning. В диагностике `mode` различает
`decision`, `speech`, `review`; приватное обоснование хранится в trace.speech этапа decision.

Контрольные прогоны 22 сентября: 11,7272 ₽ суммарно (включая первый технический
прогон с неполной реконструкцией истории, не используемый для оценки стратегии).
На двух прогонах с восстановленным счётом 2:0 Мордред без reasoning выбирал Success,
с reasoning — Fail. Оба режима одобряли команду союзников. Публичная речь иногда
копировала признание в саботаже из старого чата; добавлена узкая замена явных признаний
нейтральной фразой, исходный ответ сохранён в закрытой диагностике. Это не гарантия
от всех возможных утечек. Выбор команды Персивалем остаётся нестабильным; один ответ
исчерпал 4096 выходных токенов, что корректно остановило обработку без запасного хода.
Reasoning включён по умолчанию для решений; публичная речь остаётся без него.

Повторяемая платная проверка (не часть обычного Jest): из packages/backend выполнить
`npx ts-node -r tsconfig-paths/register src/ai/evaluate.ts`.
Три восстановленные позиции проверяются в двух режимах; потолок одного прогона 15 ₽,
все траты входят в общий журнал. Fixtures восстанавливают миссии и личные проверки,
но не всю прежнюю переписку с провайдером; это контроль ситуаций, не точный replay.
После проверок из общего лимита 500 ₽ израсходовано 405,6517 ₽. Новая партия ограничена
как собственным потолком 100 ₽, так и оставшимся общим бюджетом.

### Автоматический повтор при исчерпании ответа

Если Chat Completions возвращает `finish_reason: length`, приватное решение
повторяется один раз с теми же фактами. Для решений с рассуждением первая попытка
и повтор имеют одинаковый потолок 20 000 выходных токенов.
Публичная речь аналогично допускает один повтор с 512 вместо 256 токенов,
без повторного выбора действия. В диагностике повтор имеет mode `decision-retry`,
`review-retry` или `speech-retry`. Каждая попытка отдельно резервирует бюджет и
учитывает фактический расход; первая неудачная генерация также оплачивается.
Отмена, сетевые ошибки, другие причины незавершённого ответа и отказ бюджета
не вызывают повтор. При повторном исчерпании токенов показывается точная причина
паузы; неготовое действие не применяется. Изменение относится к новым комнатам,
автоматического восстановления ранее остановленной игры нет.

### Админский доступ и публичная витрина

`getAiRoomAccess`, `createAiRoom`, `controlAiRoom` и `getAiRoomCosts` проверяют
актуальный флаг из базы, а не JWT, клиентский профиль или логин. Ошибка базы означает
отказ в доступе. Обычные команды startGame/updateOptions/lockRoom и прочие команды
владельца не управляют AI-комнатами, в том числе после отзыва админского флага.
Просмотр партий остаётся публичным.

Общие списки, roomUpdated, joinRoom и архивные ответы не содержат стоимости.
Она загружается отдельно через getAiRoomCosts (до 50 ID), только после проверки
админа. Интерфейс обновляет доступ и стоимость каждые 10 секунд и очищает их при
смене аккаунта, отключении или отказе сервера. Сервер проверяет права без этого
интервала — на каждом запросе. Приватные диагностические трассы не выдаются.

AI Arena использует словари всех шести языков: en, ru, es, pt, zh-CN, zh-TW.
Для старых архивов без сохранённой модели название восстанавливается из
`ai_decision_traces.payload.model` при загрузке лобби и комнаты. Наружу передаётся
только идентификатор модели, без каталога провайдера. Если записей нет, подпись
не показывается: текущая настройка не доказывает модель прошлой партии.

### Бюджет 700 ₽ и постулаты игроков

По запросу владельца общий лимит увеличен на 200 ₽: с 500 до 700 ₽.
Накопленный журнал расходов не сбрасывается, лимит партии остаётся 100 ₽.

В приватном ответе теперь отдельные поля: `speech` — личное основание,
`publicReason` — предназначенный для общего чата аргумент, `evidence` — до шести
новых/исправленных выводов с ключом, источником и типом proven/claim/bluff.
До 24 записей хранятся отдельно для каждого игрока до конца комнаты, доказательства
имеют приоритет. Это выводы модели, а не вычисляемая сервером стратегия; корректность
источников и дедукций Qwen всё ещё требует проверки по журналу.
Генератор публичной речи получает только открытые факты и publicReason, без приватной
причины и списка выводов. Он должен сокращать выбранный аргумент, не придумывая новый.

По умолчанию обе стороны включают себя в предложение; исключение требует конкретной
тактической причины. Участник команды из двух при одном Fail публично защищает свою
доброту, обвиняет второго и отклоняет команды с ним. Участник команды из трёх при двух
Fail обвиняет обоих остальных и отклоняет команды с ними. Это публичная позиция даже
для злого, сыгравшего Fail; в его личных выводах она остаётся блефом. Реальный собственный
Success позволяет считать эти дедукции доказательством. Три Fail из трёх раскрывают всех
участников для каждого игрока, независимо от участия.

Итоговый разбор: один запрос без reasoning, до 384 выходных токенов, фактическая история
и собственные голоса без накопленных заметок и чата. Повтор при усечении сохраняется.
Контрольные позиции: `npx ts-node -r tsconfig-paths/register src/ai/evaluate.ts --postulates`
из packages/backend (платный запуск, потолок 15 ₽, включён в общий бюджет).

Для двух явно заданных постулатов добавлен узкий серверный контроль `table-policy.ts`:
по собственному участию, размеру команды и числу Fail он задаёт публичную позицию,
оставляет только Reject при наличии обвиняемых и исключает такие составы из предложений.
Одинаково для обеих сторон, без попытки установить истинную роль обвиняемого.
Предложения по умолчанию ограничены составами с самим игроком. При отсутствии
совместимого состава — понятная пауза, а не случайный ход. Это не общий решатель игры.
Обязательная публичная фраза формируется из номера миссии и мест участников; отдельный
запрос переписывания речи в этом случае не нужен. Индекс выбранного действия переводится
обратно в исходный список, чтобы фильтрация не меняла фактически применяемое действие.

На контрольных запросах один промпт оставался ненадёжным: Моргана после двух Fail из
трёх могла одобрить команду с обвиняемыми. Поэтому эти конкретные постулаты проверяются
кодом. В повторе пятой миссии с полными фактами новая инструкция дала Reject и указала
на доказанных злых 5 и 6; это проверка одной позиции, не гарантия качества всей партии.
Контрольный итоговый разбор без reasoning стоил 0,1738 ₽.

Итог проверки изменений: 61 AI-тест прошёл, TypeScript и ESLint без ошибок.
Платные контрольные прогоны стоили 24,1263 ₽ суммарно. Остаток после них: 182,294 ₽
из общего лимита 700 ₽. С серверной проверкой Моргана отклонила состав с обоими
обвиняемыми; предложение мирного включало его самого. Однако Qwen всё ещё выбирал
плохих напарников и мог ошибаться в публичной аргументации — гарантии всей стратегии
нет. Новые механизмы памяти и инструкции требуют дальнейшей оценки на партиях.

Зритель может раскрыть/скрыть роли на столе в запущенной AI-партии. Отдельный
`getAiSpectatorRoles` возвращает только карту id → роль, проверяя реальный BotRoom,
начало игры и отсутствие запрашивающего среди участников. Доступ открыт зрителям,
включая гостей; обычные комнаты запрещены. Карта хранится локально в компоненте,
сбрасывается при смене комнаты/аккаунта и не попадает в общий state или запросы Qwen.
Для старого незавершённого архива после перезапуска сервера карта недоступна:
сохранённый публичный снимок не содержит настоящих ролей. Завершённые партии уже
раскрывают роли обычным способом.

В evidence добавлен обязательный kind: fact/deduction/testimony/prediction/bluff.
Сервер понижает certainty у testimony/prediction до claim, у bluff до bluff.
Это проверка категорий, а не серверная проверка истинности каждого вывода.
Промпт запрещает оправдывать одобрение одним желанием успеха, напоминает точное
число оставшихся отклонений и запрещает оправдывать подозреваемого обвинением другого.
Итоговый разбор получает роли, известные до раскрытия, и требует только доступных
в тот момент действий (в частности, Леди впервые доступна после второго похода).

## Production budgets and September 22 decision fixes

Production settings and rollout: [deploy/ai-production.md](../../deploy/ai-production.md).
Production has a separate persistent 30-day ledger (Moscow calendar), 3,000 RUB per
period and 200 RUB per game; development retains the 700/100 experiment ledger.
`getAiBudget` is DB-admin-only and returns limits, used/reserved funds, remaining amount
and period dates. No budget figures enter public broadcasts, including pause messages.

Single legal mission cards and truthful Lady announcements by Good do not invoke Qwen.
Decisions now receive completedMissions, rejectedProposals and approvedProposals as
separate lists, not duplicate histories. Instructions are shortened and selected by
action, with the exact inspectionResult field and a 4 Good / 3 Evil count for this room.
One truncated decision can retry without reasoning, capped at 1024 output tokens;
it no longer doubles the reasoning allowance. Both attempts remain billed and logged.
Public speech guards also reject motives about avoiding success or preserving a failure
advantage. Model error remains possible: categories are not a general logic solver.

Two saved-position checks passed with Qwen (2.8061 RUB total). A full production game
has not been run; this is not evidence that every strategic mistake is eliminated.

### Decision reliability and opening votes (September 22)

Good players without reliable information now prefer joining the opening mission instead of approving a roster of strangers. `actionFacts.openingSelfPreference` marks an early opening vote without the player; the prompt permits evidence-based exceptions and requires comparing the forced fifth leader on proposal four. This is model guidance, not a hard rejection filter. Including oneself does not prove teammates Good or guarantee the mission.

The private decision context includes factual `actionFacts`: exact current team, own seat/side, visible Evil on that team (including oneself when Evil), unresolved members and the mission's Fail threshold. These facts never enter the public speaker's allowlist. Strategy stays with Qwen; there is no backend alignment solver. Merlin's advice explicitly preserves the hidden Mordred possibility and allows a proven single-Evil team on a two-Fail mission.

Model-generated evidence is retained as at most 12 recent `modelHypotheses`, with all non-bluff certainty demoted to `claim`. Raw outputs remain in private traces for audits. The previous four decisions retain only action/stage/mission/proposal, not recycled free-form explanations. This prevents the application from promoting its own model's guesses into authoritative `proven` records, but does not guarantee the model never makes a false deduction.

End reviews receive `yourActions` with stable IDs for actual proposals, non-forced votes, own cards and Lady announcements. Forced fifth proposals are separate from votes. The model is instructed to anchor its review to an actual action and not propose doing what it already did as a correction.

Bounded paid regression command (run from `packages/backend`):

```sh
npx ts-node src/ai/evaluate.ts --production-regressions
# One mode only:
npx ts-node src/ai/evaluate.ts --production-regressions --reasoning=default
```

This uses the local experiment ledger, a 20 RUB per-run cap and existing total cap; it does not start a live game. Six fixtures cover opening votes with/without self, Merlin's fourth-mission threshold with safe/risky teams, Mordred counting himself and Percival voting on the actual roster. They preserve player-visible mission/check facts and recent chat; old voting history is omitted and altered-team controls are labelled variants. This is a diagnostic set, not a general win-rate benchmark. A mismatched expected action sets a failing exit code; explanations still require manual review.

Use `--case=<exact fixture name>` for a single production-regression fixture (5 RUB cap). Diagnostic results and limitations are recorded in `docs/superpowers/plans/2026-09-22-ai-decision-reliability.md`; rationale quality must not be inferred from the expected-choice pass flag.

### Продолжение после лимита партии

Администратор (`isAdmin === true`, проверяется в БД при каждом запросе) может нажать «Продолжить · увеличить лимит … (×2)» для живой партии, приостановленной из-за индивидуального бюджета. `controlAiRoom(..., 'resumeBudget')` удваивает текущий лимит только этой комнаты (200 → 400 → 800 ₽). Индивидуальный лимит хранится в `ai_experiment_budget.roomLimits`; расходы не сбрасываются. Общий бюджет, включая производственные 3000 ₽ за 30 дней, продолжает ограничивать каждый запрос. Если следующему запросу не хватает общего бюджета, лимит партии не меняется.

Продолжение сохраняет движок, состав команды, уже высказанные голоса, совет тёмных и выполненные итоговые обзоры. При паузе перед публичной репликой сохраняется уже оплаченное приватное решение. Одновременные команды запуска/продолжения блокируются до завершения предыдущего игрового цикла и освобождения его резерва управления. Администратор видит индивидуальный лимит через закрытый `getAiRoomCosts`; публичное состояние его не содержит.

Продолжение доступно только пока процесс сервера хранит живую комнату. Существующие архивы после перезапуска содержат публичный replay, а не приватное состояние движка: их восстановление не поддерживается. Ручная остановка завершает игру; паузы из-за ошибок модели, контекста или общего бюджета не разрешают удвоение лимита партии.

### Выбор модели

Администратор выбирает модель в лобби перед созданием новой AI-партии. Пересоздавать контейнер для переключения не нужно. Список приходит из серверного реестра:

- `qwen3.6-35b-a3b` — текущая модель по умолчанию;
- `deepseek-v4-flash` — DeepSeek V4 Flash через тот же Yandex API и ключ.

Нужно один раз совместно обновить backend и UI до версии с выбором модели; v64.1.0 ещё не поддерживает DeepSeek. `YANDEX_MODEL` теперь задаёт только начальный выбор в списке; при неподдерживаемом значении список использует Qwen. Сервер проверяет `isAdmin` и выбранный ID при каждом создании. Если комната уже существует, возвращается она без смены модели. Модель фиксируется при создании комнаты и отображается в лобби и комнате. Неизвестный ID отклоняется до создания комнаты и до резервирования расходов. Общий бюджет и индивидуальный лимит работают для обеих моделей.

`--budget-rub` задаёт предел одного контрольного прогона (до 20 ₽) внутри существующего локального экспериментального бюджета. `--case=<название>` выбирает одну ситуацию. Режим `--reasoning=none` отдельно проверяет короткие ответы без рассуждения, используемые для публичных реплик.

Контроль 23.09.2026: DeepSeek выбрал ожидаемые действия во всех 6 фиксированных ситуациях (`reasoning=default`, 8.153 ₽). Отдельная проверка публичной реплики с `reasoning=none` прошла за 0.8838 ₽. Итого 9.0368 ₽. Максимальная длительность ситуации — 80.16 с. Это проверка совместимости и выбранных действий, а не полная партия или доказательство превосходства над Qwen; приватные объяснения отдельно не оценивались. Результаты: [2026-09-23-deepseek.json](../ai-evaluations/2026-09-23-deepseek.json).

### Ожидание модели

Каждый HTTP-запрос к модели (решение, публичная реплика, повторная попытка и итоговый обзор) может выполняться до **10 минут**. Это общий дедлайн получения ответа и его тела; администратор может прервать его раньше кнопкой остановки. Только AI-запросы используют сетевой dispatcher с соответствующими таймаутами. Блокировка партии удерживается 12 минут от последнего резервирования запроса и освобождается при завершении игрового цикла. Таймаут не увеличивает лимиты расходов; неподтверждённая стоимость сохраняется резервом. Дополнительных параметров env не требуется.

### Reasoning output limit

Game decisions with reasoning enabled start with 20,000 output tokens. The one automatic focused retry and a roster-consistency repair also use 20,000; retries do not increase this ceiling. Public speech retains its smaller limit. Post-game reviews now use one reasoned call with a 20,000-token ceiling when reasoning is enabled; there is no separate draft-check call. Every attempt reserves and charges usage against the existing room and shared budgets.

Production defaults to 200 RUB per game; the first explicit administrator budget continuation raises that room to 400 RUB without resetting spending. The shared 3000 RUB / 30-day limit is unchanged. If production explicitly sets `AI_MATCH_BUDGET_RUB=150`, update that setting to `200` on deployment; environment overrides the default. Previously persisted per-room extensions are retained. Development remains 100 RUB per game.

### Public Percival claims and explicit positions

Merlin, Percival and Evil bots may use `claimMorgana` on a public decision to intentionally claim Percival and accuse a seat of being Morgana. The server appends a canonical statement in the room’s discussion language after public-speech sanitization. Other bots receive these declarations as public testimony, never as verified roles or private knowledge. On their next scheduled public decision each must return `claimStances` with an explicit `trust` or `distrust` for every other claimant. Missing, duplicate or invalid positions stop publication; there are no additional paid discussion rounds. Instructions require explaining the stance, making teams/votes consistent with it, and explaining any change. Deterministic Good Lady-result announcements remain truthful and do not introduce an extra decision call. Claims remain available from the archived public chat even when the ordinary recent-chat window has moved on.

Evil card instructions compare the immediate benefit of Fail with the concrete future value of a cover Success, account for the score and required Fail count, and describe a shared seat-order sabotage convention to avoid unnecessary double Fails. These are model instructions, not a server strategy solver. Good opening instructions distinguish self-preference from a blanket veto and explicitly consider the forced fifth leader. Merlin safety and assassination instructions distinguish privileged early knowledge from deductions everyone can make after public evidence.

A narrow consistency check detects explicitly selected bracketed rosters in a private explanation that contradict the action. One billed `decision-repair` can correct the action or explanation using the same facts and legal choices; a repeated mismatch pauses before applying the action. This is not a general natural-language verifier. Reviews now ask for one reasoned first-person causal analysis anchored to the actual outcome and recorded decision examples, rather than a second model critique of a draft.

## Локальные партии через Codex / ChatGPT

В development доступен отдельный провайдер `codex-chatgpt`, использующий текущую
авторизацию Codex CLI в ChatGPT. В `.env.local` добавьте:

```dotenv
AI_ROOMS_ENABLED=true
AI_CODEX_ENABLED=true
# При необходимости — абсолютный путь к установленному Codex CLI:
AI_CODEX_BIN=/path/to/codex
# Если авторизация хранится в отдельном профиле:
AI_CODEX_HOME=/path/to/codex-profile
```

Перезапустите локальный backend, войдите под администратором, в лобби выберите
**Codex · ChatGPT**, создайте AI-комнату, раскройте панель **Арена ИИ** и выберите
модель Codex и поддерживаемую глубину рассуждений. Рядом с моделями показана одна условная цена API: самая дешёвая доступная модель с известным тарифом = $1. Сравнение использует одинаковое число некэшированных входных и выходных токенов по стандартным тарифам короткого контекста; это не стоимость партии и не расход лимита подписки Codex. Тарифы проверены 01.10.2026 и хранятся в `packages/ui/src/helpers/codex-pricing.ts`; неизвестная модель показывается без оценки цены. При нажатии **Start AI match**
настройки сохраняются в комнате и фиксируются для всех запросов партии. Каталог
берётся из локального `codex debug models` и кешируется на пять минут; его загрузка
не блокирует права администратора и кнопку Stop. После запуска смена модели
и глубины отклоняется сервером. Stop отменяет
активный процесс; после технической паузы доступно повторение. `codex login status`
должен показывать ChatGPT для выбранного профиля. API-ключи backend не передаются
процессу Codex. В production этот вариант отсутствует и отклоняется сервером,
даже если установить `AI_CODEX_ENABLED=true`.

Используются лимиты подписки; рублёвый бюджет Яндекса не списывается. Панель
рублёвой стоимости скрыта для Codex. Память и разделение приватного решения и
публичной речи остаются в существующем pipeline. Каждый вызов создаёт отдельную
временную сессию в пустой папке, с отключёнными shell, unified exec, web search,
apps, plugins, browser и image tools; временные файлы удаляются после вызова.
Диагностика сохраняется в штатных закрытых коллекциях AI. Отдельной истории
диалогов CLI нет. Партия может идти долго: обычно один публичный ход включает
два последовательных запроса. Этот режим предназначен для локального тестирования.

### Постоянные AI-персонажи

Новая AI-комната выбирает пять, шесть, семь или восемь разных персонажей из пула десяти в `packages/backend/src/ai/agents.ts` равномерным перемешиванием Fisher–Yates через `crypto.randomInt`. Состав выбирается один раз при создании и сохраняется при запуске и продолжении. Роли раздаются независимо обычным игровым движком.

Severin (аналитик), Lada (дипломат), Ray (азартный экспериментатор), Vera (хранительница), Mark (провокатор), Nika (независимая), Oscar (капитан), Mira (наблюдательница), Leo (верный союзник), Thea (напористая обвинительница) имеют постоянные ID `avalon-agent-1`…`avalon-agent-10`, английские имена и разные существующие аватарки. Аватарка не обозначает игровую роль. Карточка профиля и всплывающая карточка показывают характер на языке интерфейса (ru, en, es, pt, zh_CN, zh_TW) через стабильный ключ `aiPersona.key`. Инструкции модели написаны на английском. Прежние ID `avalon-ai-*` сохраняют старые имена и аватарки в архивных партиях.

Ray предпочитает ранние эксперименты с новыми правдоподобными командами, но прекращает рискованные пробы при двух провалах. Leo формирует круг доверия на основе поведения и защищает союзников до появления опровергающих фактов. Thea выбирает подозреваемого по публичным противоречиям, задаёт конкретные вопросы и требует ответов, не считая уклонение доказательством. На стороне Зла эти характеры адаптируют тактику к цели своей стороны.

Предпочтения личности входят в контекст решений, публичных реплик и итогового разбора. Это мягкие предпочтения при неопределённости: правила, проверенные факты, ограничения видимости, цель своей стороны и защита Мерлина имеют приоритет. Характер не даёт новых знаний и не выбирает ответ вместо модели. Проверки с подставным решателем подтверждают передачу характера; влияние на живые решения нужно оценивать по партиям.

### Статистика AI-профилей

Обычная страница `/stats/user/<id>/` для новых `avalon-agent-*` и прежних `avalon-ai-*` персонажей использует завершённые партии из `ai_room_replays`. На ней доступны общий винрейт, результаты по сторонам и ролям, последние партии, союзники и противники. Незавершённые партии и ручное завершение не учитываются. История загружается страницами по 200 компактных записей без приватных контекстов; после загрузки даты старых и новых архивов разбираются для хронологического порядка. Уже сохранённые завершённые партии доступны без переноса в коллекцию человеческих игр.

Чтение архива работает при отключённой генерации AI, если подключена база данных. Общая статистика сайта, достижения и топ ролей по-прежнему используют человеческие партии. AI-профиль показывает один общий TrueSkill (старт 6000) по той же формуле, что человеческие профили, и статистические результаты по ролям без отдельных рейтингов ролей. Общий AI-рейтинг начинается с 6000 для десяти `avalon-agent-*` персонажей и восстанавливается только по завершённым партиям текущего сезона (`ai.profileRatingSeason = 1`) в порядке времени. Эта метка назначается при создании новой комнаты после установки релиза с рейтинговым сезоном; старые комнаты автоматически не размечаются. Прежние партии остаются в статистике, но не влияют на новый рейтинг. Старые `avalon-ai-*` боты не имеют рейтинга; повторное сохранение партии не удваивает её вклад. Ответ обычного `getTrueSkillRating` для AI берётся из этого отдельного расчёта, без записи в коллекции человеческих рейтингов и без включения AI в человеческий топ. Расчёт кешируется на 15 секунд и инвалидируется при сохранении архива.

В описаниях AI-партий нет подписи `unranked`. В списке комнат и панели показывается реальная выбранная модель (например, `gpt-6.1-sol`), а `codex-chatgpt` остаётся идентификатором провайдера внутри сервера. До выбора модели в лобби значение Model не показывается.

### Передача Леди озера и цепочка доверия

При сопоставимой информационной и тактической пользе допустимых проверок бот Света предпочитает передать Леди игроку, чья принадлежность к Свету поддержана надёжными сведениями. Проверяемый становится следующим владельцем, поэтому последовательность честных проверок может продолжать направленную цепочку доверия. Если Леди получает игрок Тьмы, его дальнейшие объявления не считаются надёжным продолжением этой цепочки без независимого подтверждения; прежние достоверные проверки сохраняют силу. Это предпочтение при равных вариантах, а не замена более важной проверки, и неизвестный игрок не считается подтверждённым Светом. Боты Тьмы сохраняют цель своей стороны и могут стремиться перехватить Леди или нарушить доверие Света. Инструкция на английском передаётся обоим провайдерам через общий pipeline; сервер не выбирает цель вместо модели.

### Остаток недельного лимита Codex

В панели Codex-партии администратор видит остаток недельного лимита аккаунта и время его обновления. Backend читает `account/rateLimits/read` через `codex app-server` с теми же `AI_CODEX_BIN` и `AI_CODEX_HOME`, которые используются для решений ботов. Запрос не запускает модель; в браузер передаются только процент остатка, время сброса и время чтения. Недельное окно определяется по длительности 10080 минут в общем bucket `codex`, независимо от расположения в primary/secondary; отсутствие окна или ошибка отображаются как недоступность, не как нулевой остаток. Успешное чтение кешируется на минуту, неудачное — на 10 секунд; UI обновляет значение раз в минуту. Это общий лимит аккаунта, включая работу вне игры, а не оценка оставшегося количества партий. Данные доступны только администратору при включённом локальном Codex; public room state не содержит квоту.

## Язык и живое обсуждение AI-партии

Перед созданием AI-комнаты рядом с моделью выбирается язык общения: `en`, `ru`
или `zh-tw` (традиционный китайский, Тайвань). Он сохраняется в `ai.language`,
виден в лобби и комнате и передаётся во все запросы ботов: решения, публичную
речь, закрытый совет злых и итоговый разбор. Серверные объявления голосований,
составов, проверок Леди, заявлений о Персивале и итоговых сообщений используют
тот же язык. Старые комнаты и старый вызов `createAiRoom(model, callback)`
сохраняют английский по умолчанию. Новый клиент передаёт
`createAiRoom({ model, language }, callback)`; неподдерживаемый язык отклоняется
до резервирования бюджета комнаты. JSON-ключи и допустимые значения игровых
действий остаются прежними.

Обычная реплика допускает до двух коротких предложений и 240 символов:
конкретный довод и уместный адресный вопрос или ответ. В свой следующий ход бот
сначала отвечает на вопрос или возражение к нему из доступного недавнего чата.
Если такого вопроса нет, он может предложить компромисс или задать один полезный
вопрос; спрашивать на каждом ходу не требуется. Характер влияет на манеру речи:
дипломат предлагает компромисс, провокатор задаёт точный вопрос, лоялист защищает
обоснованное доверие, аналитик выбирает решающий факт, азартный игрок называет
конкретный риск. Манера речи не отменяет цель стороны, факты, легальность
действия и секретность. Объявления сервера и обязательные заявления о роли
могут добавлять текст поверх этого лимита. Обсуждение проходит до окончательного
выбора команды; голосование после него не сопровождается новой дискуссией.

Предварительные предпочтения отмечаются `publicDiscussion` в памяти модели
и как `discussion` в приватных заметках для зрителей, чтобы не считать их
отправленной командой. При повторе усечённого ответа обсуждение и окончательный
выбор сохраняют недавний чат, включая полный круг. Обязательные позиции по
публичным заявлениям о Персивале выражаются во время обсуждения; необязательное
объявление окончательного состава может оставаться пустым. Тихие голоса не
создают заявлений о роли даже при обязательном отклонении по постулатам стола.

При бюджетной или технической паузе сохраняются выполненные выступления,
окончательный выбор и уже собранные голоса. Не сохранённая из-за ошибки реплика
допубликуется при продолжении из готового ответа без повторного обращения к модели.
Повтор использует тот же идентификатор сообщения, чтобы не дублировать запись
при сбое после вставки в БД.
Предел 400 обращений комнаты покрывает базовый максимум 371 на семь ботов для
пяти миссий с пятью попытками каждая. На восемь ботов максимум составляет 418,
поэтому технический предел равен 450. Дополнительные запросы голосования
увеличивают число обращений к модели; действующие лимиты расходов и резервы сохраняются.

Мерлин получает короткую проверку авторства: при сопоставимой безопасности и
возможности собрать большинство предпочесть поддержку уже публично
обоснованного состава постоянному выдвижению своих новых чистых команд. Это
критерий выбора между сопоставимыми вариантами; при угрозе миссии или
достижимому большинству следует предложить нужный состав самому.

Перед убийством злые кратко рассматривают каждого допустимого кандидата,
включая тихих последователей, затем сравнивают двух сильнейших. Проверяют,
можно ли объяснить раннюю точность публичными фактами, включением себя или
знаниями Персиваля. Общий для кандидатов довод их не различает; чистый состав,
его позднейший успех и повторы совета не считаются независимыми уликами.
