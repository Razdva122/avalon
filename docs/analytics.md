# Аналитика регистрации и начала игры

Клиент отправляет события в существующий Google Analytics через `gtag`.
Точки отправки: `helpers/acquisition.ts`, `AuthModal.vue`, `WelcomeModal.vue`
и обновления состояния комнаты в `Room.vue`.

## Авторизация

| Событие                                 | Условие                                                                                                                                                                                                 |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auth_open`                             | Открытие окна авторизации, включая повторное открытие.                                                                                                                                                  |
| `auth_tab`                              | Переключение вкладки входа/регистрации в открытом окне.                                                                                                                                                 |
| `auth_dismiss`                          | Пользователь закрывает окно; `reason=close` или `password_recovery`. Успешный вход сюда не попадает.                                                                                                    |
| `sign_up_attempt`                       | Отправка формы регистрации.                                                                                                                                                                             |
| `sign_up_error`                         | Отклонение регистрации сервером или сетевой сбой.                                                                                                                                                       |
| `sign_up`                               | Сервер подтвердил создание аккаунта, даже если окно успели закрыть.                                                                                                                                     |
| `auth_result`                           | Успешная регистрация с контекстом исходного действия.                                                                                                                                                   |
| `login_attempt`, `login_error`, `login` | Отправка, отказ и успешный результат входа.                                                                                                                                                             |
| `auth_continue`                         | Авторизация завершилась в актуальном окне: `continued` — сохранённый сценарий, `welcome` — регистрация без сценария, `stay` — обычный вход. Это выбор маршрута, а не подтверждение выполнения действия. |

Контекст: `page` — категория страницы, `mode` — `auth`/`registration`,
`action` — `account`, `create_room`, `join_room`, `ai_game`, `publish_listing`
или `chat`. `error` содержит только известный код; неизвестные значения
заменяются на `other`. Отменённые и устаревшие ответы не отправляют
`auth_continue`, но фактический результат серверной авторизации учитывается.

## Приветственное окно

| Событие             | Условие                                                                                                                                 |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `welcome_view`      | Показ после регистрации; `reason=signup`.                                                                                               |
| `welcome_ai_status` | Изменение доступности AI в открытом окне.                                                                                               |
| `welcome_choice`    | Выбор AI, поиска компании или создания комнаты для друзей.                                                                              |
| `welcome_result`    | Успех/ошибка открытия AI-комнаты или создания комнаты для друзей.                                                                       |
| `welcome_dismiss`   | Закрытие: `close`, `later`, `outside` (фон/Escape), `navigation` (выбранное действие). Повторное закрытие не создаёт повторное событие. |

`choice`: `ai`, `community`, `friends`. Выбор AI означает открытие настроек
или переход в уже подготовленную комнату, а не запуск партии. Успешный
`welcome_result` означает переход в комнату. Поиск компании измеряется
выбором; этот переход не означает, что компания найдена.

## Игровые результаты

Существующие `room_participation` и `human_game_complete` сохранены.
Для публичных AI-игр добавлены `ai_room_participation` и `ai_game_complete`.
Участие фиксируется только для пользователя в составе игроков. Завершение —
по живому обновлению партии, в которой клиент ранее наблюдал участие.
Просмотр архива, зрители, снимок уже законченной игры и ручная отмена
не считаются завершением. Административные AI-комнаты исключены.

## Отчёты и ограничения

Полезные воронки:

- `auth_open` → `sign_up_attempt` → `sign_up`;
- `welcome_view` → `welcome_choice` → участие → завершение игры;
- регистрация по `action` → участие в человеческой или AI-игре;
- ошибки регистрации по коду и доля закрытий приветствия без выбора.

Для отчётов зарегистрируйте в GA событийному уровню параметры `page`,
`action`, `mode`, `error`, `choice`, `reason`, `result`, `availability`.
Для исходного SEO-источника сохранён параметр `guide_slug`.
Воронки необходимо строить по пользователям и порядку событий: простое
отношение общего числа кликов к показам искажается повторными попытками.

Новые события не содержат email, логин, имя, пароль, текст сообщений,
ID пользователя/комнаты/партии или исходный URL. Значения параметров
проверяются по списку разрешённых категорий; URL события заменён на
корень сайта. Это относится к добавленным событиям и не меняет существующий
автоматический сбор просмотров страниц.

Дедупликация игровых событий действует в памяти вкладки и сбрасывается
при полной перезагрузке. «Первая игра» означает первую наблюдаемую в
выбранной воронке, а не доказанную первую игру аккаунта за всё время.
Нет серверного восстановления пропущенных событий. Блокировка аналитики
и prerender не мешают приложению. Доставку в GA нужно проверить после
публикации; локальные тесты подтверждают формирование событий.
