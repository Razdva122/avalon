# OxaPay: оплата поддержки и Premium

Avalon создаёт hosted invoice в USD через OxaPay API v1. Накопленные подтверждённые взносы от $10 дают Premium навсегда. Учитывается номинал полностью оплаченного счёта до комиссии сервиса. Повторное уведомление не увеличивает сумму.

## Настройка

Создайте Merchant API Key в OxaPay. Сохраните настройки в окружении backend или игнорируемом `packages/backend/.env.local`. Не добавляйте ключ в Git, frontend или Docker-образ.

```dotenv
OXAPAY_MERCHANT_API_KEY=your-merchant-key
OXAPAY_SANDBOX=true
OXAPAY_CALLBACK_URL=https://avalon-game.com/api/support/oxapay/ipn
SUPPORT_FRONTEND_URL=https://avalon-game.com
```

Без ключа приём платежей отключён. Отсутствующий `OXAPAY_SANDBOX` означает `true`; только явное `false` включает реальные счета. Backend нужно перезапустить после изменения окружения. В Docker передайте настройки контейнеру backend при запуске; локальный файл сам по себе не меняет конфигурацию продакшена.

Монеты и сети выбираются на странице OxaPay и настраиваются в merchant account. Если нужен только USDT, ограничьте принимаемые активы в кабинете. API hosted invoice не фиксирует выбранную сеть отдельным параметром. Пользователь сверяет точную криптосумму, минимум и комиссию сети на странице оплаты.

## Проверка перед включением

1. Проверьте доступность merchant account и API с production-сервера. Замена провайдера сама по себе не доказывает отсутствие региональных ограничений.
2. Создайте sandbox-счёт через Avalon. Проверьте переход на OxaPay и завершение тестовой оплаты. История должна показывать тестовый счёт и `test_paid`; Premium, общая сумма и публичная лента не меняются.
3. Убедитесь, что OxaPay доставляет POST на callback URL. Endpoint принимает JSON с заголовком `hmac`. Проверяется HMAC-SHA512 исходных байтов тела с Merchant API Key, затем статус повторно запрашивается через API. Успешный ответ — текст `ok`.
4. После успешной проверки задайте `OXAPAY_SANDBOX=false`, перезапустите backend и проверьте один реальный платёж, историю, сумму и активацию Premium. Не меняйте режим уже созданных счетов: он сохраняется в каждом заказе.

Без Merchant API Key тесты используют подменённые ответы OxaPay. Это проверяет приложение, но не доступность сервиса, настройки аккаунта или реальный расчёт.

## Учёт и восстановление

Webhook не является источником суммы или статуса. Backend получает платёж по `track_id` и сверяет локальный счёт, `order_id`, тип `invoice`, валюту USD и сумму. Premium начисляется только при `paid` и `under_paid_coverage=0`. `manual_accept`, недоплата и возврат на рассмотрении не дают Premium. Sandbox никогда не попадает в сумму поддержки.

Кнопка «Проверить оплату» запрашивает сохранённый `track_id`, даже если webhook не дошёл. Для оператора в окружении backend:

```sh
npx ts-node src/scripts/reconcileSupport.ts TRACK_ID
```

Команда только сверяет существующий счёт. Она не создаёт платежи и не переводит средства. Завершённые счета неизменяемы; автоматического отзыва бессрочного Premium после последующего возврата нет.

Старый обработчик NOWPayments и его конфигурация удалены. По разрешению владельца 17 сентября 2026 года удалены пять старых счетов `creation_failed`, без созданного счёта провайдера; оплаченных счетов среди них не было. Миграция не содержит автоматического удаления данных при запуске. Старые ключи NOWPayments в окружении больше не используются и могут быть удалFены при настройке OxaPay.
