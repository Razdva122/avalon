# Подключение NOWPayments к Avalon

Интеграция добавлена в код; реальные платежи отключены, пока не настроены все переменные. Учёт: сумма полностью оплаченных завершённых счетов в USD до комиссии сервиса. От $10 суммарно — бессрочный Premium. Оплата только в выбранной сети USDT; точную сумму токенов рассчитывает NOWPayments. Для каждого нового пожертвования создавайте новый счёт: каждый invoice засчитывается один раз, даже если оплатить его повторно. Переплата не увеличивает номинал счёта, частичная оплата автоматически не засчитывается. Первое преимущество Premium — значок; коллекции косметики пока не объявляются.

## 1. Аккаунт и кошельки

1. Зарегистрируйтесь на https://account.nowpayments.io/ и выполните требования сервиса для вашего аккаунта.
2. При включённом Custody кошельки вывода можно добавить позже: средства поступают на баланс NOWPayments. Перед выводом уточните комиссии, минимумы и условия вывода для небольших платежей. Адреса на платёжных страницах принадлежат инфраструктуре NOWPayments; ваш постоянный адрес используется для вывода.
3. Выберите три доступные сети USDT в кабинете. Сверьте API-коды через список валют API, настройте приём/вывод без нежелательного обмена. Код не навязывает «самую популярную» тройку; неизвестные или недоступные сети не следует включать.
4. Создайте API key и отдельный IPN secret. Не присылайте их в чат и не добавляйте в git. Включите IPN и проверьте настройки допуска webhook на стороне сервиса.

## 2. Серверные переменные

Добавьте секреты в окружение процесса backend или в игнорируемый `packages/backend/.env.local`. Backend запускается с рабочей директорией `packages/backend`; `.env.local` читается до `.env.production` и не перекрывает уже заданные переменные процесса.

```dotenv
NOWPAYMENTS_API_KEY=
NOWPAYMENTS_IPN_SECRET=
NOWPAYMENTS_CALLBACK_URL=https://avalon-game.com/api/support/nowpayments/ipn
SUPPORT_FRONTEND_URL=https://avalon-game.com
NOWPAYMENTS_USDT_CURRENCIES=
```

Последняя переменная — три проверенных кода валют через запятую. Пример формата кода: `usdttrc20`. Это не подтверждение доступности сети вашему аккаунту. Любая незаполненная переменная отключает checkout; страница поддержки остаётся доступной. Ключи не должны попадать в `VUE_APP_*`.

Настройте в NOWPayments такой же IPN callback URL. HTTPS endpoint должен быть доступен извне без авторизации пользователя. Запросы проверяются по подписи HMAC-SHA512. Nginx-конфигурация репозитория дополнена проксированием `/api/support` на backend: при развёртывании нужно применить также этот конфиг. MongoDB должен разрешать создание уникальных индексов SupportOrder до приёма запросов.

## 3. Проверка перед запуском

- Без ключей: страница сообщает, что оплата не настроена, создание счёта возвращает 503.
- С ключами: войдите в тестовый аккаунт Avalon, выберите сеть и сумму. Предварительная проверка не пропускает сумму ниже минимума NOWPayments.
- Проверьте реквизиты, сумму USDT и комиссию на платёжной странице. Настоящий платёж и вывод выполняет владелец проекта после проверки настроек.
- Убедитесь, что счёт получает `finished`, вклад учитывается один раз, а Premium включается при сумме от $10.
- Повторите доставку IPN: итог не должен увеличиться. `confirmed`, `partially_paid` и возврат браузера не дают Premium.
- Проверьте анонимный взнос, затем скрытие всех предыдущих взносов и отдельно значка.
- Повторите проверку каждой из трёх сетей и вывод на кошелёк проекта.

Автотесты используют фиктивные ключи, provider HTTP fixtures и изолированные хранилища; они не создают реальные платежи. Эта интеграция обращается к production API только при наличии конфигурации. Не подставляйте sandbox-ключи: отдельный sandbox checkout здесь не реализован.

## 4. Потерянные уведомления и спорные оплаты

История доступна владельцу аккаунта. «Проверить оплату» получает актуальный статус через API, если хотя бы одно уведомление уже сохранило payment ID. Если не пришло ни одного IPN, интерфейс сообщает о необходимости проверки, а не объявляет оплату успешной.

Оператор находит платёж в NOWPayments по Avalon order ID и повторяет доставку IPN из кабинета. Альтернатива: восстановление по **payment ID NOWPayments**, не по хешу блокчейн-транзакции:

```sh
cd packages/backend
NODE_ENV=production npx ts-node src/scripts/reconcileSupport.ts 123456789
```

Скрипт получает платёж непосредственно из API и проверяет его исходный order ID, invoice ID, валюту и сумму. Он не позволяет назначить платёж другому аккаунту или выдать статус без проверки. API key и IPN secret берутся из серверного окружения. Команда сама не переводит деньги.

Статус `review` означает, что сервис прислал `finished`, но фактическая сумма ниже требуемой: проверьте счёт в кабинете. Не меняйте БД для обхода проверки; сначала разберите доплату/возврат с NOWPayments. Уже зачтённый `finished` не понижается запоздавшими событиями. Возврат после окончательного завершения и споры требуют отдельной операторской обработки; автоматического отзыва Premium в первой версии нет.

Анонимность скрывает имя на Avalon, но не делает блокчейн приватным. Публичная лента не содержит user ID, адреса, payment ID или хеш транзакции. Сумма показана в USD по номиналу счёта, день — в UTC. Страница, баннер и SEO-тексты переведены на все шесть языков сайта.

## Подготовка релиза с временно скрытым баннером

Баннер поддержки на главной отключён через `v-if="false"` в `Lobby.vue` до проверки платежей на production. Страница `/support/` доступна по прямой ссылке; скрытие баннера не ограничивает доступ к оплате.

Секретные `.env.production` и `.env.local` исключены из Docker build context. Передайте переменные backend при запуске контейнера через `--env-file` или настройки окружения хостинга. Локальный `.env.production` не переносится через Git или Docker-образ.

Публикация Docker-образов запускается push тега `v*.*.*`; workflow сам не обновляет контейнеры на сервере. В релиз должны попасть backend и UI (образ UI включает обновлённый nginx). Локальная база `avalon-dev` и демонстрационные донаты не переносятся на production.

Перед приёмом оплаты проверьте, что API NOWPayments возвращает настроенные валюты, callback доступен снаружи, а счёт проходит путь до `finished` с однократным начислением Premium. Ранее `/currencies` возвращал пустой список; проверка исправлена на `/merchant/coins` (см. ниже). Список в локальной production-конфигурации: `usdttrc20,usdterc20,usdt`; третий код необходимо сверить с нужной сетью и доступностью в аккаунте.

## Доступные сети и минимумы

Доступность сетей проверяется через `/v1/merchant/coins` (`selectedCurrencies`, регистр нормализуется). `/v1/currencies` не используется для проверки валют аккаунта. Публичный `/api/support/networks` возвращает минимумы для каждой настроенной сети в USDT и USD, рассчитанные по текущей оценке обмена и округлённые вверх до цента (не меньше $1). Кэш — 60 секунд; сбой одной сети не скрывает остальные. При недоступности данных checkout этой сети блокируется, пользователь может обновить сведения. Создание счёта независимо повторяет проверки доступности, оценки и минимума.

## Диагностика HTTP 429 (17 сентября 2026)

На backend v61.0.2 воспроизведено: параллельные `/estimate` для трёх сетей дают HTTP 429 для Ethereum и BNB, тогда как TRON проходит. Все валюты есть в `/merchant/coins`; последовательные запросы из того же контейнера успешны. Поэтому сообщение о недоступности сетей не означало отсутствие поддержки валют аккаунтом.

Исправление загружает минимумы последовательно, повторяет GET после 429 не более одного раза (пауза по числовому Retry-After, максимум 5 секунд, по умолчанию 1 секунда). POST создания счёта автоматически не повторяется. Серверные сообщения `NOWPayments request failed` содержат endpoint без payment ID, сеть, HTTP-статус и только известные коды ошибок; ключи, тела запросов и произвольные сообщения провайдера не выводятся. API различает `not_enabled` и `lookup_failed`.

Форма выбирает сеть, доступную для начальных $10, сохраняет доступный выбор при обновлении и предлагает кнопку установки минимума, если сумма недостаточна. Пресеты ниже минимума отключены. Текущие минимумы не следует записывать как постоянную цену Premium.

Проверки: `npm run test --workspace=packages/backend -- --runInBand`, `npm run test:support --workspace=packages/ui`, `npm run build:ui`. После публикации **обоих** образов и обновления контейнеров проверьте `/api/support/networks`, создание счёта и реальный IPN. Проверка минимумов сама не создаёт счёт и не доказывает прохождение платежа до `finished`.
