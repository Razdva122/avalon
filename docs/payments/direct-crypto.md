# Прямые переводы: BTC и USDT

Пользователь переводит произвольную сумму, затем указывает сеть и txid. Сайт проверяет фактическое поступление на адрес владельца и начисляет поддержку. Накопленные $10 дают Premium. Адрес отправителя вместо txid не поддерживается: пользователь получает подсказку, где взять хеш, или обращается к команде.

## Настройка

Донаты включены по умолчанию: дополнительные переменные Docker Compose не нужны. Адреса кошельков и публичные API заданы в `packages/backend/src/support/direct/config.ts`. Используются четыре адреса:

| Переменная           | Адрес                                                            |
| -------------------- | ---------------------------------------------------------------- |
| SUPPORT_BTC_ADDRESS  | `bc1qn63r5d5qd0rnq7l9v2kp75rx9c5jsh9m22v09ru9dy3t3hutt8zqksv2nv` |
| SUPPORT_TRON_ADDRESS | `TLmpR98uorxHmAULuG5JwDpaxKv7j5Zmvq`                             |
| SUPPORT_ETH_ADDRESS  | `0xE37cA64A14dD8e92929B7E71f3DA32267Da5969a`                     |
| SUPPORT_BSC_ADDRESS  | `0xE37cA64A14dD8e92929B7E71f3DA32267Da5969a`                     |

Провайдеры по умолчанию (эти переменные можно использовать для необязательного переопределения):

```dotenv
SUPPORT_BTC_API_URL=https://mempool.space/api
SUPPORT_TRON_API_URL=https://api.trongrid.io
SUPPORT_ETH_RPC_URL=https://ethereum-rpc.publicnode.com
SUPPORT_BSC_RPC_URL=https://bsc-rpc.publicnode.com
```

Это публичные провайдеры; их доступность и квоты зависят от провайдера. Можно переопределить URL своим HTTPS endpoint совместимого API. Отсутствующая переменная использует значение из кода; явно пустая строка отключает только соответствующую сеть. Для TronGrid при необходимости задайте `SUPPORT_TRON_API_KEY`. Приватные ключи кошельков сайту не передаются.

Флаг `DIRECT_SUPPORT_ENABLED` удалён и больше не используется. Для стандартной настройки достаточно обновить образы backend и UI. Только при переопределении настроек через окружение передайте переменные контейнеру и пересоздайте его.

Перед показом сети пользователю сервер проверяет её доступность, mainnet и поддержку необходимых методов; результат кешируется на минуту. Недоступная сеть не показывается в новом платеже. Уже сохранённые заявки остаются в истории и перепроверяются. В RPC можно использовать ключ в пути или query; он не попадает в публичный API.

## Активы и подтверждения

| Сеть            | Принимаемый актив                                                          | Подтверждение                                                   |
| --------------- | -------------------------------------------------------------------------- | --------------------------------------------------------------- |
| Bitcoin         | BTC, native SegWit mainnet-адрес                                           | **1 подтверждение**, hash блока соответствует текущей цепочке   |
| Ethereum        | USDT `0xdac17f958d2ee523a2206206994597c13d831ec7`, 6 decimals              | Успешный receipt, канонический и finalized блок                 |
| BNB Smart Chain | Binance-Peg USDT `0x55d398326f99059ff775485246999027b3197955`, 18 decimals | Успешный receipt, канонический и finalized блок                 |
| TRON            | USDT `TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t`, 6 decimals                      | Успешный receipt SolidityNode и наличие txid в solidified блоке |

BEP20 здесь означает указанный Binance-Peg токен. Другие контракты с названием USDT не учитываются. Для EVM RPC нужны `eth_chainId`, `eth_getTransactionReceipt`, `eth_getBlockByNumber` с тегом `finalized`, `eth_call` для проверки decimals. TRON использует `/walletsolidity/gettransactioninfobyid`, `/walletsolidity/getblockbynum` и `/walletsolidity/getnowblock`. Bitcoin API совместим с Esplora.

Одно подтверждение BTC выбрано владельцем для наград сайта. После завершённого начисления автоматического отзыва при последующей реорганизации нет; спорные ситуации разбираются оператором.

## Суммы и заявки

USDT учитывается по $1. Для BTC используется публичный Coinbase Exchange ticker BTC-USD: курс не старше пяти минут фиксируется **при успешной проверке сайтом**, а не по времени блока. Если пользователь ввёл старый txid, применяется курс обработки сейчас. Недоступный/устаревший курс не даёт начисления; сайт повторяет проверку. Суммы обрабатываются целыми минимальными единицами, долларовый результат округляется вниз до цента. Перевод меньше цента сохраняется с нулевым долларовым вкладом.

Несколько выходов/событий одной транзакции на выбранный адрес суммируются. Первая успешно проверенная заявка получает начисление. Уникальный индекс MongoDB по paymentID запрещает повторное начисление той же сети, транзакции, актива и адреса. Txid публичный и не доказывает авторство — это сознательно принятая владельцем схема с ручным разрешением споров.

При запуске backend создаёт необходимые индексы до запуска проверки. Не отключайте уникальный индекс paymentID. Новая заявка и ручная проверка ограничены одной операцией в минуту на аккаунт. Повторное открытие завершённого результата не запрашивает блокчейн повторно.

Фоновый обработчик запускается с backend, берёт до 10 заявок за проход, затем ждёт 15 секунд. Аренда отдельной заявки — 2 минуты; после остановки процесса другой обработчик заберёт её по истечении аренды. Интервал перепроверки растёт от минуты до часа. Через час после подачи txid автоматические проверки заканчиваются; пользователь может проверить снова вручную. Сетевой сбой не помечает перевод как отклонённый.

## Спорные начисления

Из директории `packages/backend` с настроенным окружением базы:

```sh
npx ts-node src/scripts/reassignSupport.ts ORDER_ID CURRENT_USER_ID NEW_USER_ID 'Причина переноса'
```

Команда переносит только завершённое начисление между существующими аккаунтами. Передаётся ожидаемый текущий владелец, чтобы повтор команды или параллельное изменение не перенесли запись неожиданно. Сумма, txid и уникальный paymentID не меняются. В той же записи атомарно сохраняются старый/новый аккаунты, дата и причина. При переносе взнос становится анонимным. Premium определяется заново по итогам обоих аккаунтов; независимый ручной Premium не отзывается. Команда не переводит криптовалюту.

## Проверка перед включением

1. Запустите backend и проверьте `GET /api/support`: нужные четыре сети должны появиться, RPC URL и ключей в ответе быть не должно.
2. Авторизуйтесь и проверьте адреса, выбор сети, копирование и ввод txid. Тесты приложения используют фиктивные ответы блокчейна и временную MongoDB — они не переводят средства.
3. После отдельного решения владельца проверьте небольшой реальный перевод в каждой нужной сети. Убедитесь в правильной сумме, анонимности, истории и Premium при достижении порога.
4. Повторная отправка того же txid должна вернуть прежний результат; другой аккаунт получает сообщение о ранее учтённом переводе. Не публикуйте txid вместе с личными данными плательщика.

OxaPay полностью удалён по уточнению владельца: он не был подключён. Старые обработчики, ключи, ссылки и команды больше не используются; автоматического удаления данных из базы нет.
