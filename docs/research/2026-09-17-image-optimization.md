## Рекомендуемая реализация

1. **Генерировать варианты из неизменяемых оригиналов на сборке.** Для портретов ориентир — 256/512/1024 px; выбирать через srcset/sizes. 1024 нужен для крупных wiki-портретов и увеличенных лиц. В PlayerIcon CSS масштабирует картинки до 230%: учитывать размер элемента × background-size × DPR; нельзя выбирать размер только по внешней рамке. Для CSS использовать подходящие варианты и image-set, либо управляемый выбор URL по месту использования. Оригиналы хранить отдельно от автоматически подключаемых production-файлов, чтобы require.context не публиковал лишние мастеры.
2. **Перевести premium PNG и стикеры в WebP.** Для premium начать с q80–85 и проверки лиц/украшений; для стикеров отдельно сравнить lossy и lossless с сохранением alpha. Размер 320 у стикеров уже разумный, большой выигрыш здесь даёт формат. Не переводить растровые иллюстрации в SVG и не применять JPEG к прозрачным стикерам.
3. **Добавить loading=lazy только вне первого экрана**, прежде всего длинные каталоги ролей и коллекций. SchemaImage, Avatar и StickerImage сейчас не задают loading, srcset или sizes. Первые видимые портреты и LCP должны загружаться сразу. Браузер подгружает lazy-картинки заранее около экрана, поэтому нельзя обещать, что загрузятся строго 6 из 20. Для CSS backgrounds loading не работает. Сохранить/задать размеры или aspect-ratio там, где они ещё не зарезервированы; decoding=async рассмотреть для второстепенных картинок. [Рекомендации web.dev](https://web.dev/articles/browser-level-image-lazy-loading).
4. **Добавить AVIF как опциональный источник с WebP fallback**, после основных улучшений. На наших пробах max512 AVIF меньше WebP для основной группы ролей примерно на 37%, для anime — на 33%. Но нужны индивидуальные настройки качества и тесты декодирования на целевых устройствах. Для HTML — picture, для CSS — fallback/image-set. [Форматы MDN](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Image_types), [адаптивные изображения web.dev](https://web.dev/learn/design/responsive-images).
5. **Ввести проверки бюджета в CI.** Стартовые ориентиры после визуальной настройки: thumb до 256 — 15 КиБ, portrait до 512 — 40 КиБ, до 1024 — 100 КиБ, sticker320 — 40 КиБ; сначала предупреждения и обоснованные исключения. Проверять alpha, размеры, MIME, доступность каждого варианта и соответствие manifest. Порог не должен заставлять портить сложные изображения. Зафиксировать версии кодеков и настройки, чтобы повторная сборка давала стабильные bytes/hash.

## Что важно сохранить в доставке

Существующие contenthash-имена, годовой immutable-кэш и загрузку новых файлов до публикации контейнера оставить. Повторный визит выигрывает от кэша, но кэш не устраняет большой первый download и декодирование чрезмерного разрешения. Наличие всех URL в JavaScript не означает скачивание всех изображений — фактические запросы измерены отдельно.

При оптимизации появятся новые хеши и несколько осмысленных размеров. Старые объекты не удалять: отложенный rollout, старые вкладки и откат должны продолжать работать. Bucket/CDN не заменяет генерацию подходящих размеров; подключение CDN не является первым приоритетом этого аудита, задержки по регионам не измерялись.

AVIF сейчас не поддержан нашим pipeline целиком: helpers/images/index.ts жёстко выбирает PNG для premium/stickers; check-images.cjs и upload-images.cjs принимают PNG/WebP, uploader явно задаёт их MIME. Также аудитор сейчас ожидает копии исходников по checksum: при введении производных нужен manifest «исходник → варианты» и обновление проверки. Просто положить .avif в assets недостаточно. Согласованно обновить helper, сборку/генерацию, CSS/HTML, manifest, проверку и uploader (image/avif); сохранить проверку всех опубликованных URL перед контейнером.

## Порядок и пределы выводов

Первый этап: адаптивные WebP + premium/stickers + lazy для дальних изображений. Второй: AVIF там, где визуальная проверка подтверждает пользу. Третий: измерить холодную/повторную загрузку, LCP/CLS и память на слабом телефоне, закрепить бюджеты.

Игровую сессию на production не создавали, авторизованные коллекции не обходили; для них проверен код, но нет сетевого замера. Полноэкранный сезонный фон не уменьшать по общему правилу для иконок. Не измерялись скорость AVIF-декодирования, производительность на реальном телефоне и региональный RTT. Не заявляем ускорение в секундах: приведённые выигрыши — размеры файлов. В этом исследовании нет изменения приложения или релиза.
