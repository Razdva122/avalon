# Consistent standalone MongoDB backups

Copy `backup-mongodb.sh` beside `activate-app.sh` in `/opt/avalon/voice-release` when deploying the updated release tooling. The activation script calls the helper before replacing the application.

The helper takes MongoDB's `fsyncLock`, dumps all databases into a private temporary file, validates gzip integrity, unlocks, then publishes the archive. MongoDB reads continue; all writers, including background workers, wait during the dump. Schedule the operation during a maintenance window: long dumps can exceed application write timeouts. Root credentials remain inside the container environment and are never printed by the scripts. Do not run with shell tracing.

The helper serializes backups with `/var/lock/avalon-mongodb-backup` (override with `MONGODB_BACKUP_LOCK_DIR` only for an isolated deployment/test host). It refuses an already locked database. The acquisition-attempt flag is recorded before contacting Docker, so an applied server lock followed by a failed response or HUP/INT/TERM still triggers state-checked cleanup. Ordinary command failure and HUP/INT/TERM invoke cleanup and unlock. If the deployment host/process is forcibly killed, the Docker connection is lost during lock acquisition, or unlocking fails, check MongoDB's lock state and explicitly run `db.getSiblingDB('admin').fsyncUnlock()` through an authenticated administrative shell before allowing another deployment. SIGKILL cannot be trapped. If unlock cannot be verified, the host mutex is deliberately retained; remove it only after inspecting and recovering the MongoDB lock. Never run concurrent database backup/lock operations from another host or administrative shell: MongoDB fsync locks have no ownership token, so those operations must follow the same exclusive maintenance discipline.

The archive is a database-consistent point-in-time view; it does not make application operations spanning multiple writes transactional. Gzip verification is not a restore drill. Regularly restore an archive into a separate disposable MongoDB, inspect collection counts and application invariants, and keep encrypted copies off the application VM. This repository does not configure production backup scheduling or off-host storage.
